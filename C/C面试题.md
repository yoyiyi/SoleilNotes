## 一、语言基础

### Q1 static 的三种作用？
**答**：
- 修饰局部变量：存储期变成静态，只初始化一次、值跨调用保留，但作用域仍在块内。
- 修饰全局变量或函数：链接属性变为内部链接，只在本翻译单元可见，用来隐藏实现、避免多文件重名。
- 第三种是 C++ 的静态成员，C 里没有，被问到时点明即可。
- 一句话记法：**局部 static 管生命周期，全局 static 管可见性**。

### Q2 volatile 的作用？
**答**：
- 告诉编译器这个对象可能被程序之外的东西改变，每次都必须真正读写内存，不能缓存进寄存器、不能删掉"看起来没用"的读写。
- 典型场景：硬件寄存器、中断服务程序里修改的变量、信号处理函数里的标志、忙等待的共享标志。
- 易错点：它不保证原子性、不提供内存屏障、也不解决竞态，`volatile int` 的 `i++` 依然不是原子操作。

### Q3 const 与 #define 的区别？
**答**：
- `const` 有类型、有作用域、参与编译期类型检查、调试器能看到符号；`#define` 是预处理阶段的纯文本替换，无类型无作用域。
- 宏容易踩优先级（`#define N 1+2` 后 `N*2` 变成 5）、无法取地址；`const` 对象有地址，能传指针。
- 取舍：常量优先 `const`/`enum`，宏只留给条件编译、头文件卫士、字符串化与记号拼接。
- 补一句边界：C 里的 `const` 不是常量表达式，不能当 `case` 标签，数组维度会退化成 VLA。

### Q4 sizeof 和 strlen 的区别？
**答**：
- `sizeof` 是编译期运算符，算类型或对象占的字节数；`strlen` 是运行期函数，从首地址走到第一个 `'\0'`，不含 `'\0'`。
- `sizeof("hello")` 是 6，`strlen("hello")` 是 5；`sizeof(char *)` 永远是指针大小，跟字符串多长无关。
- 数组作为参数退化后，函数内 `sizeof(arr)` 只得到指针大小，长度必须另外传。
- `sizeof(arr) / sizeof(arr[0])` 只在数组尚未退化的作用域里成立。

### Q5 i++ + i++ 为什么是未定义行为？
**答**：
- 两个自增之间没有序列点（C11 起叫"无顺序"），同一表达式里对同一对象多次修改且没有顺序约束，标准不规定先算哪一个。
- 所以结果可能是 `2i`、`2i+1`、`2i+2`，随编译器和优化级别变化；`i = i++ + 1`、`a[i] = i++` 同理。
- 面试答法：先定性"这是 UB，不能写"，再给原因"缺序列点"，最后给正确写法 `int t = i; i += 2;`。
- 顺带区分：`&&`、`||`、`?:`、逗号运算符带序列点，所以 `i++ && i++` 是有定义的。

### Q6 什么是左值和右值？
**答**：
- 左值指可定位的存储（有地址、能放在赋值左边），右值是临时值（只有值、没有持久地址）。
- C 里的判断标准就是能不能取地址：`&x` 合法则 `x` 是左值；数组名、函数名是左值但不可赋值（不可修改左值）。
- `i++` 的结果是旧值副本（右值），`++i` 的结果是自增后的值，在 C 里仍不是左值，C++ 里才是左值。
- 延伸：结构体整体赋值要求左边是可修改左值，函数返回结构体给的是右值。

### Q7 register 和 auto 现在还有用吗？
**答**：
- `auto` 是局部变量的默认存储类，C 里几乎不写；C23 起它有了类型推导的新语义（`auto x = 1;`），老代码别依赖。
- `register` 只是"建议放寄存器"：不能取地址（`&i` 直接编译错误），现代编译器自己做寄存器分配，这个关键字基本被忽略。
- 结论：两者都该从新代码里消失，面试答"历史遗留 + C23 语义变化"最稳。

### Q8 inline 和宏有什么区别？
**答**：
- 宏是预处理文本替换：没有类型检查、参数可能被多次求值、调试看不到符号、作用域是整个文件。
- `inline` 是给编译器的建议：有类型检查、参数只求值一次、遵循作用域，是否真正内联由编译器决定（`-O0` 通常不内联）。
- 头文件里放函数定义要用 `static inline`（C99），否则多个 `.o` 会报重复定义。
- 结论：能用 `static inline` 就别用宏，宏只保留需要"文本能力"的场合（字符串化、拼接、条件编译）。

## 二、指针与内存

### Q9 指针和数组的区别？
**答**：
- 类型不同：`int a[5]` 的类型是 `int[5]`，`int *p` 是指针；`sizeof` 分别是 20 和 8（64 位）。
- 数组名代表整块数组，不能赋值、不能自增；指针是变量，可以改指向、可以自增。
- 数组名在大多数表达式里退化为首元素指针，但 `sizeof`、`&`、`_Alignof` 和字符串初始化字符数组时不退化，`&a` 的类型是 `int (*)[5]`。
- 函数参数里的数组一律退化为指针，`void f(int a[5])` 中 `sizeof(a)` 是 8。

| 对比项 | `int a[5]` | `int *p` |
| --- | --- | --- |
| `sizeof` | 20 | 8（64 位） |
| 赋值 | `a = ...` 非法 | 可重新指向 |
| `&` 的类型 | `int (*)[5]` | `int **` |
| 作参数 | 退化为指针 | 本身就是指针 |

### Q10 数组指针和指针数组怎么区分？
**答**：
- 看优先级：`[]` 优先于 `*`，所以 `int *p[3]` 是"指针数组"（3 个 `int *`），`int (*p)[3]` 是"数组指针"（指向 `int[3]`）。
- 指针数组常存字符串表：`const char *names[] = {"a", "b"};`；数组指针用于二维数组传参：`void f(int (*a)[3], int rows)`。
- 记忆：括号把 `*` 和名字绑在一起就是数组指针，`p + 1` 跨越整个 `int[3]`（12 字节）。
- 再延伸一级：`int **pp` 是二级指针，用来在函数里修改"指针本身"，比如 `void alloc(int **out)`。

### Q11 函数指针和回调是什么关系？
**答**：
- 函数指针保存函数入口地址：`int (*fp)(int, int) = add;`，调用 `fp(1, 2)` 与 `(*fp)(1, 2)` 完全等价。
- 把函数指针作为参数传进去，由被调方在合适时机调用，这就是回调；`qsort` 的比较函数是标准例子。
- 典型用途：`qsort`/`bsearch`、事件分发、状态机的跳转表（函数指针数组）、驱动注册。
- 易错：`int *f(int)` 是返回指针的函数，`int (*f)(int)` 才是函数指针，括号不能省；`typedef` 能显著提升可读性。

### Q12 const 修饰指针的四种写法？
**答**：
- `const int *p` 和 `int const *p`：指向常量的指针，不能改 `*p`，可以改 `p`。
- `int * const p`：常量指针，必须初始化，可以改 `*p`，不能改 `p`。
- `const int * const p`：数据和指针都锁死，两者都不能改。
- 口诀：**const 在 `*` 左边锁数据，在 `*` 右边锁指针**；从变量名往外读，"指针/只读"交替念。

| 写法 | 改 `*p` | 改 `p` |
| --- | --- | --- |
| `const int *p` | 否 | 是 |
| `int const *p` | 否 | 是 |
| `int * const p` | 是 | 否 |
| `const int * const p` | 否 | 否 |

### Q13 void * 有什么用？
**答**：
- 通用对象指针：任何对象指针都能隐式转成 `void *`，也能隐式转回，C 里不需要强制转换（C++ 需要）。
- 用途：`malloc`/`calloc`/`realloc` 的返回类型，`memcpy`/`memmove`/`qsort` 的参数，通用容器或回调的上下文参数。
- 限制：不能解引用（不知道类型和大小）、不能做指针算术（GCC 按 1 字节扩展，标准不允许）；转回具体类型前不能读写。
- 易错：`void *` 不等于"任意函数指针"，对象指针和函数指针互转在标准里不可移植。

### Q14 野指针和悬垂指针是怎么来的？怎么防？
**答**：
- 野指针：未初始化的指针（`int *p; *p = 1;`）、指向已释放内存的指针、指向已退出函数栈帧的指针。
- 悬垂指针是其中一种：`free` 后没置 `NULL`、返回局部数组地址、`realloc` 搬走后旧指针没更新。
- 防守三板斧：定义即初始化（`int *p = NULL;`）、`free` 后立刻 `p = NULL`、写清所有权（谁分配谁释放）。
- 工具：`-Wall -Wextra` 加 ASan 能抓到大部分 use-after-free 和 stack-use-after-return。

### Q15 malloc 失败怎么处理？
**答**：
- `malloc` 返回 `NULL` 表示失败，必须检查，不能直接解引用，也不能假设"内存一定够"。
- 处理方式：`perror("malloc")` 打印原因、向上返回错误码、或走降级路径；库函数里不要直接 `exit`。
- 嵌入式和安全规范场景（MISRA、部分车规）常常禁止动态分配，改成静态内存池或启动时一次性分配。
- 细节：`malloc(0)` 可能返回 `NULL` 或一个可 `free` 的唯一指针；`free(NULL)` 安全；失败后原指针状态不受影响。

### Q16 realloc 为什么要用临时指针？
**答**：
- `realloc` 成功返回新地址（可能等于原地址），失败返回 `NULL` 且**原块保持不变**。
- `p = realloc(p, n)` 一旦失败，`p` 被覆盖成 `NULL`，原内存再也 `free` 不掉，直接泄漏。
- 正确写法：`tmp = realloc(p, n); if (tmp == NULL) { /* p 仍有效 */ } else { p = tmp; }`。
- 另外：`realloc` 可能搬移数据，成功后旧指针失效，新增部分不会清零；`realloc(p, 0)` 在 C23 前是实现定义。

### Q17 内存泄漏怎么定位？
**答**：
- 先看代码模式：分配后丢失指针、提前 `return` 没走到 `free`、循环里只分配不释放、错误分支漏 `free`。
- 工具：Linux 用 `valgrind --leak-check=full`，GCC/Clang 用 `-fsanitize=address`（LeakSanitizer 默认开启），IDE 也有内存分析器。
- 读报告看 `definitely lost` 的**分配点**调用栈，而不是 `free` 点；`still reachable` 常常是全局缓存，不一定算泄漏。
- 工程手段：统一封装 alloc/free、成对释放用 `goto cleanup`、CI 里固定跑一遍 ASan。

### Q18 栈和堆有什么区别？
**答**：
- 栈由编译器和 OS 管理，函数进入分配、返回回收，速度快、空间小（Linux 默认 8 MB），放局部变量和调用帧。
- 堆由 `malloc`/`free` 管理，手动释放，空间大、速度慢、容易碎片化，生命周期由程序员控制。
- 栈向低地址增长，堆向高地址增长；递归过深或超大局部数组会栈溢出（`ulimit -s` 可调）。
- 易错：`char buf[1 << 20]` 放栈上可能直接崩，应该 `malloc` 或改 `static`。

| 对比项 | 栈 | 堆 |
| --- | --- | --- |
| 管理方 | 编译器 + OS | 程序员（malloc/free） |
| 速度 | 快（移动栈指针） | 慢（分配器查找） |
| 大小 | 几 MB | 受物理内存/地址空间限制 |
| 碎片 | 无 | 有 |

### Q19 传值和传址有什么区别？
**答**：
- C 只有传值调用：实参的值被拷贝给形参，函数内改形参不影响实参。
- 想要修改实参就传地址（指针），函数内用 `*p` 写回，这就是常说的"传址调用"。
- 数组传参会退化成指针，函数内能改元素，但拿不到数组长度，必须另传。
- 结构体传值是整体拷贝，大结构体应传 `const struct S *`，需要修改时传非 const 指针。

### Q20 指针运算的边界在哪？
**答**：
- 只能在同一数组（或同一对象）内部运算；指向"最后一个元素的下一个位置"合法，可比较、可计算，但不能解引用。
- 两个指针相减要求指向同一数组，结果类型是 `ptrdiff_t`，单位是元素个数而不是字节数。
- 指针越界本身就是 UB（哪怕不解引用），编译器优化时可能做出反直觉的事；跨对象比较同样没有定义。
- `p + 1` 前进 `sizeof(*p)` 字节，`(char *)p + 1` 才前进 1 字节。

### Q21 malloc、calloc、realloc 有什么区别？
**答**：
- `malloc(n)` 分配 n 字节、内容随机；`calloc(n, size)` 分配 `n * size` 并清零，内部检查乘法溢出。
- `realloc(p, n)` 调整已分配块的大小，可能搬移数据；失败返回 `NULL` 且原块有效，所以要用临时指针接。
- 三者失败都返回 `NULL`，都必须判空；`free(NULL)` 安全，重复 `free` 是 UB。
- 选型：数组或需要零值用 `calloc`，扩容用 `realloc`，普通结构体用 `malloc`。

| 对比 | `malloc` | `calloc` | `realloc` |
| --- | --- | --- | --- |
| 参数 | 总字节数 | 个数 + 单元素大小 | 原指针 + 新大小 |
| 清零 | 否 | 是 | 否（新增部分） |
| 溢出检查 | 调用方 | 内部检查 | 调用方 |

### Q22 memcpy 和 memmove 有什么区别？
**答**：
- `memcpy` 不处理重叠，重叠时行为未定义；`memmove` 保证重叠也正确。
- `memmove` 的做法：比较 `dst` 与 `src` 的地址，`dst < src` 从前向后拷，否则从后向前拷。
- 选型：确定不重叠用 `memcpy`（通常更快），不确定就用 `memmove`。
- 共同点：都不检查目标大小、都不补 `'\0'`、参数是 `void *`、长度单位是字节。

## 三、结构体与联合

### Q23 结构体的内存对齐规则是什么？为什么要对齐？
**答**：
- 规则一：每个成员的偏移量必须是其对齐数的整数倍，不够就插填充字节。
- 规则二：结构体总大小必须是最大对齐数的整数倍（末尾补齐），这样数组里每个元素都对齐。
- 原因：CPU 按总线宽度成块取数，对齐后一次就能读到；部分架构（早期 ARM、MIPS）未对齐访问直接异常，x86 上是性能损失。
- 代价是填充浪费空间：把大对齐成员放前面、大致按对齐数从大到小排，通常能减小 `sizeof`。

### Q24 结构体的 sizeof 怎么算？举个例子。
**答**：
- 手算步骤：偏移从 0 开始，每个成员先对齐再占位，最后整体按最大对齐数取整。
- `struct A { char c; int i; short s; };` → `c@0`、补 3、`i@4`、`s@8`、尾部补 2，共 12。
- `struct B { char c; short s; int i; };` → `c@0`、补 1、`s@2`、`i@4`，共 8；只是换了顺序就省下 4 字节。
- `struct C { double d; char c; };` → 8 + 1 补齐到 16；空结构体是 GNU 扩展，C 里为 0，C++ 里为 1。

### Q25 #pragma pack 的作用和风险？
**答**：
- 作用：改变对齐上限，`#pragma pack(push, 1)` 取消填充、`#pragma pack(pop)` 恢复，常用于网络协议、文件格式、硬件寄存器结构。
- 好处：结构体布局与协议字节流一一对应，可以直接 `memcpy` 收发，省掉逐字段解析。
- 风险：成员地址可能未对齐，部分平台访问变慢甚至触发 `SIGBUS`；不同编译器对 pack 的实现细节也有差异。
- 建议：跨平台协议别依赖结构体内存布局，用显式序列化；至少加 `_Static_assert(sizeof(T) == N, "");` 做编译期检查。

### Q26 位域怎么用？有什么限制？
**答**：
- 写法：`struct { unsigned a : 3; unsigned b : 5; }`，按二进制位分配，用来表示开关量、协议字段、硬件寄存器。
- 规则：宽度不能超过底层类型位宽；剩余位不够时另起一个单元；`unsigned : 0` 强制从下一单元开始；无名位域只做填充。
- 限制：不能取地址（`&s.a` 非法）、不能定义数组、位序和布局由实现定义，大小端不同平台的位序也可能不同。
- 结论：跨平台协议别用位域直接对字节流，改用移位和掩码。

### Q27 共用体有什么用？怎么用它判断大小端？
**答**：
- 所有成员共享同一块内存，同一时刻只有一个成员有效；`sizeof` 等于最大成员的大小，再按最大对齐数取整。
- 用途：节省内存、同一块数据多视角解释（协议字段、浮点的位模式）、判断大小端。
- 代码：

```c
union { unsigned int i; unsigned char c[4]; } u = { .i = 1 };
if (u.c[0] == 1) puts("little-endian");   /* 低地址放低字节 → 小端 */

unsigned int x = 1;
if (*(unsigned char *)&x == 1) puts("little-endian");   /* 指针法，等价 */
```

- 注意：类型双关的结果依赖字节序和实现，协议解析别依赖它，显式用移位和 `htonl` 更稳。

### Q28 柔性数组是什么？
**答**：
- C99 特性：结构体最后一个成员写成 `char data[];`，长度运行时决定，`sizeof` 不包含它。
- 用法：`struct packet *p = malloc(sizeof *p + n);` 一次分配头部加数据，内存连续、只需一次 `free`。
- 好处：相比 `char *data` 少一次分配、少一次间接寻址、缓存更友好；相比 `char data[0]`（GCC 扩展）是标准写法。
- 约束：必须是最后一个成员、结构体至少还有一个其他成员、长度要自己存，不能用 `sizeof` 求。

### Q29 结构体能包含自身吗？自引用怎么写？
**答**：
- 不能包含自身类型的成员（大小无法确定），但可以包含指向自身的指针：`struct node { int v; struct node *next; };` 这就是链表和树。
- 两个结构体互相引用时先做不完整声明：`struct B;` 再写 `struct A { struct B *p; };`。
- `typedef` 自引用要小心：`typedef struct node { struct node *next; } node;` 可以，因为标签在 `{` 之前已可见；`typedef struct { node *next; } node;` 不行。
- 结构体定义只是声明类型、不分配空间，定义变量时才分配。

### Q30 结构体传参、赋值和比较要注意什么？
**答**：
- 结构体可以整体赋值（`b = a`，按成员逐字节拷贝的语义），但不能用 `==` 比较，要逐成员比较或 `memcmp`。
- `memcmp` 的坑：填充字节的内容不确定（只有赋值或 `memset` 后才稳定），含指针时比较的是地址不是内容。
- 传参是值拷贝：大结构体传 `const struct S *`，需要修改传非 const 指针；小结构体返回值拷贝可以接受。
- 含指针或柔性数组的结构体不能浅拷贝后各自 `free`，要么写深拷贝，要么明确所有权。

## 四、编译链接与预处理

### Q31 从源码到可执行文件经历哪几个阶段？
**答**：
- 预处理（`-E`）：展开 `#include`、`#define`，处理条件编译，删注释，产出 `.i`。
- 编译（`-S`）：词法、语法、语义分析加优化，产出 `.s` 汇编。
- 汇编（`-c`）：汇编器翻译成机器指令，产出可重定位目标文件 `.o`。
- 链接：符号解析加段重定位，把 `.o` 和库合成可执行文件；`gcc -v` 能看到它实际调用的 `cc1`/`as`/`ld`。

### Q32 .a 和 .so 有什么区别？
**答**：
- `.a` 静态库：`ar rcs libfoo.a foo.o` 生成，链接时把用到的 `.o` 复制进可执行文件，体积大、部署简单、无运行时依赖。
- `.so` 共享库：`gcc -shared -fPIC` 生成，链接时只记录依赖，运行时由动态链接器加载，体积小、可共享、升级方便。
- 注意：`.so` 必须用 `-fPIC` 编译；静态库链接顺序有讲究，被依赖的库放后面。
- 排查：`nm` 看符号、`ldd` 看动态依赖、`readelf -d` 看 `SONAME`；`-static` 强制静态链接。

| 对比 | `.a` | `.so` |
| --- | --- | --- |
| 链接时机 | 编译期复制 | 运行期加载 |
| 体积 | 大 | 小 |
| 升级 | 需重新链接 | 替换文件即可 |

### Q33 static 修饰全局变量和函数，在链接层面是什么效果？
**答**：
- 文件作用域的 `static` 是内部链接：符号只在本翻译单元可见，不进动态符号表，别的 `.o` 链接不到。
- 普通全局定义是外部链接；`extern` 是声明外部符号、不分配空间（写 `extern int x = 1;` 反而是定义）。
- 用途：隐藏实现细节、避免多文件重名；`nm` 里 static 函数是小写 `t`，外部函数是大写 `T`。
- 常见报错：只有声明没有定义 → `undefined reference`；两个 `.o` 定义同一强符号 → `multiple definition`（GCC 10 起默认 `-fno-common`）。

### Q34 头文件卫士为什么需要？#pragma once 呢？
**答**：
- 防止同一头文件被重复包含（A 包含 C、B 也包含 C），导致类型、宏、内联函数重复定义。
- 卫士写法：`#ifndef X_H` / `#define X_H` / …… / `#endif`，按宏去重，标准且可移植。
- `#pragma once` 按文件去重，写法短、编译更快，但不是标准；同一文件的不同路径副本（软链接）会失效。
- 头文件只放声明：函数原型、`extern` 变量、类型定义、宏、`static inline` 函数；定义放 `.c`，否则多文件链接重复定义。

### Q35 extern "C" 是干什么的？
**答**：
- C++ 编译器会对函数名做名字修饰（name mangling），C 编译器不做；两边符号名对不上就链接失败。
- `extern "C"` 让 C++ 按 C 的规则生成和解析符号，从而能链接 C 编译出的 `.o` 或 `.a`。
- 标准写法放在 C++ 侧头文件里，并用 `#ifdef __cplusplus` 包住，让同一份头文件 C 和 C++ 都能用：

```c
#ifdef __cplusplus
extern "C" {
#endif

int add(int a, int b);

#ifdef __cplusplus
}
#endif
```

- C 源文件本身不需要它；是 C++ 调用方负责声明，C 代码照常用 C 编译器编译。

### Q36 宏有哪些坑？怎么写得安全？
**答**：
- 参数和整体都要加括号：`#define SQ(x) ((x) * (x))`，否则 `SQ(1 + 2)` 展开成 `1 + 2 * 1 + 2`。
- 参数可能被多次求值：`MAX(i++, j++)` 会让其中一个变量自增两次，改用 `static inline` 函数。
- 多语句宏用 `do { ... } while (0)` 包起来，才能像函数一样加分号使用。
- 宏没有类型检查、没有作用域、调试看不到符号；`#define N 100;` 多写一个分号是经典事故。

### Q37 typedef 和 #define 有什么区别？
**答**：
- `typedef` 由编译器处理，有作用域、有类型检查；`#define` 是预处理文本替换，无类型、无作用域。
- `typedef int *P; P a, b;` 两个都是 `int *`；`#define P int *` 后 `P a, b;` 只有 `a` 是指针，`b` 是 `int`。
- `typedef` 能给复杂类型起名：`typedef int (*cmp_t)(const void *, const void *);`，宏做不到这种"类型"能力。
- 组合类型也要注意：`typedef int A[10];` 定义的是数组类型；用宏表达不了同样的语义。

## 五、未定义行为与调试

### Q38 数组越界和缓冲区溢出为什么危险？
**答**：
- 越界写会踩坏相邻变量、返回地址、堆块头，轻则数据错乱，重则崩溃或被利用执行任意代码。
- `strcpy`/`strcat`/`sprintf` 都不检查目标大小：`char buf[8]; strcpy(buf, "0123456789");` 溢出 3 字节。
- 安全替代：`snprintf(buf, sizeof buf, "%s", s)`、`fgets`、`strncpy` 后手动补 `'\0'`。
- `strncpy` 的坑：src 太长时不补 `'\0'`，src 太短时又把剩下的 n 字节全填 0。

### Q39 有符号整数溢出为什么是未定义行为？
**答**：
- 标准规定有符号溢出是 UB，编译器可以假设它不发生，从而做激进优化，严重时整个检查分支被删掉。
- 无符号溢出是回绕（mod 2^N），行为有定义，所以哈希、校验、位运算常用无符号类型。
- 判溢出不要"先加再判断"，写 `if (a > INT_MAX - b)`，或用 `__builtin_add_overflow`。
- 实际危害：`if (len + 1 < len)` 这类写法会被优化掉，安全漏洞经常出在这里。

### Q40 free 之后继续使用会怎样？
**答**：
- use-after-free 是 UB：内存可能已被分配器复用或还给 OS，读到的值不可预期，写会破坏别人的数据。
- double free 同样是 UB，glibc 会打印 `double free or corruption` 并 abort；`free(p + 1)`、`free(&local)` 也非法。
- 防守：`free` 后立刻 `p = NULL`（对 `NULL` 做 `free` 是安全的），所有权写清楚，别让多个指针指向同一块。
- 工具：ASan 直接报 `heap-use-after-free` 并给出分配、释放、使用三处调用栈，valgrind 也能抓到。

### Q41 函数返回局部数组为什么错？
**答**：
- 局部数组在栈上，函数返回后栈帧失效，返回的地址指向已回收的内存，就是悬垂指针。
- 编译器通常只报 warning（`-Wreturn-local-addr`）；运行结果"看起来对"是运气，多调用一次就变。
- 三种修法：调用方传缓冲区（最推荐）、`static` 数组（不可重入、非线程安全）、`malloc` 由调用方 `free`。
- 变体：返回局部结构体是合法的（整体拷贝），返回数组名才错；返回字符串字面量也可以（静态存储期）。

### Q42 gets 为什么被标准移除？
**答**：
- `gets` 读一行到缓冲区，却完全不知道缓冲区多大，任何长度的输入都能溢出，无法安全使用。
- C11 起从标准中删除（C99 已标记为废弃），现在只在老代码和教材里能见到。
- 替代：`fgets(buf, sizeof buf, stdin)`（会保留换行，需要自己删）、`getline`（POSIX，动态分配）。
- Annex K 的 `gets_s` 是可选接口，很多实现不提供，跨平台不要依赖。

### Q43 怎么用 ASan 和 gdb 定位一次数组越界？
**答**：
- 第一步开告警：`-Wall -Wextra -Wpedantic`，很多越界（常量下标、明显溢出）编译期就有提示。
- 第二步上 Sanitizer：`gcc -g -O1 -fsanitize=address,undefined demo.c -o demo`，ASan 会给出越界类型（`stack-buffer-overflow`）、地址和精确行号。
- 没有 ASan 的平台：gdb 里 `bt` 看调用栈、`p i` 看下标、`x/16xb arr` 看内存，用 `watch` 盯住被踩坏的变量反推写入者。
- 线上兜底：`-fstack-protector-strong` 放 canary，配合 core dump 的 `bt full` 分析。

## 六、手写代码

### Q44 手写 strlen？
**答**：
- 先确认接口：返回 `size_t`、不含 `'\0'`、入参 `const char *`。

```c
size_t strlen(const char *s)
{
    const char *p = s;

    while (*p != '\0') {
        p++;
    }
    return (size_t)(p - s);
}
```

- 要点：指针相减得到长度（单位是元素）、不要用 `int` 接返回值、`while (*p++)` 写法会多走一步要小心。
- 工程细节：自己实现时函数名加 `my_` 前缀，避免和标准库的同名符号冲突。
- 加分：说明标准库实现会按机器字长一次读 8 字节、用位运算找零字节，但面试写出清晰版本即可。

### Q45 手写 strcpy 有哪些坑？
**答**：
- 关键点：返回 `dst` 以支持链式调用、必须拷贝结尾 `'\0'`、`src == dst` 时也要能工作。

```c
char *strcpy(char *dst, const char *src)
{
    char *ret = dst;

    while ((*dst++ = *src++) != '\0') {
        ;
    }
    return ret;
}
```

- 缺点：不检查 `dst` 大小、不处理重叠（重叠要用 `memmove`），调用方必须自己保证空间够。
- 工程替代：`snprintf(dst, size, "%s", src)` 能截断并保证结尾，或 `strncpy` 后手动补 `'\0'`。

### Q46 手写 memcpy，并考虑重叠？
**答**：
- `memcpy` 的前提是不重叠；要支持重叠就写 `memmove`，按地址高低决定拷贝方向。

```c
void *memcpy(void *dst, const void *src, size_t n)
{
    unsigned char *d = dst;
    const unsigned char *s = src;

    while (n--) {
        *d++ = *s++;
    }
    return dst;
}

void *memmove(void *dst, const void *src, size_t n)
{
    unsigned char *d = dst;
    const unsigned char *s = src;

    if (d < s) {
        while (n--) *d++ = *s++;        /* 目标在低地址：从前向后 */
    } else if (d > s) {
        d += n; s += n;
        while (n--) *--d = *--s;        /* 目标在高地址：从后向前 */
    }
    return dst;
}
```

- 要点：必须转成 `unsigned char *` 才能做字节算术（`void *` 不能加减）、`d < s` 正序拷、`d > s` 逆序拷、相等直接返回。
- 加分：说明 `memcpy` 重叠是 UB 而非"结果不对"，现代编译器会用内建实现并假设不重叠。

### Q47 手写 atoi？
**答**：
- 要处理的边界：前导空白、正负号、非数字终止、int 溢出。

```c
int my_atoi(const char *s)
{
    long v = 0;
    int sign = 1;

    while (*s == ' ' || (*s >= '\t' && *s <= '\r')) {
        s++;
    }
    if (*s == '+' || *s == '-') {
        sign = (*s++ == '-') ? -1 : 1;
    }
    while (*s >= '0' && *s <= '9') {
        v = v * 10 + (*s++ - '0');
        if (v > INT_MAX) {
            return (sign > 0) ? INT_MAX : INT_MIN;
        }
    }
    return (int)(sign * v);
}
```

- 注意：需要 `#include <limits.h>`；标准 `atoi` 溢出是 UB，自己写要定策略（饱和或报错）；工程里优先 `strtol`，它用 `errno == ERANGE` 报溢出。
- 边界自测：空串返回 0、`"-0"` 返回 0、`"  +12abc"` 返回 12。

### Q48 反转单链表（C 语言）？
**答**：
- 三指针迭代：先存后继、再掉头、最后整体前移，时间 O(n)、空间 O(1)。

```c
struct node {
    int val;
    struct node *next;
};

struct node *reverse(struct node *head)
{
    struct node *prev = NULL;

    while (head != NULL) {
        struct node *next = head->next;   /* 先存后继，否则丢失后半段 */
        head->next = prev;                /* 掉头 */
        prev = head;                      /* prev 前移 */
        head = next;                      /* head 前移 */
    }
    return prev;                          /* 循环结束时 prev 是新头 */
}
```

- 易错：先改 `head->next` 再保存后继就丢了链表；空链表和单节点要能直接返回。
- 递归写法更短但栈深度 O(n)，长链表会栈溢出，面试先给迭代版。

### Q49 判断大小端，写两种方法？
**答**：
- 思路：看最低地址字节里放的是不是最低有效字节；小端是，大端不是。

```c
int is_little_endian(void)          /* 指针法 */
{
    unsigned int x = 1;
    return *(unsigned char *)&x == 1;
}

int is_little_endian2(void)         /* 共用体法 */
{
    union { unsigned int i; unsigned char c[4]; } u = { .i = 1 };
    return u.c[0] == 1;
}
```

- 结论：x86 和默认配置的 ARM 是小端，网络字节序是大端；跨平台转换用 `htons`/`htonl`，别手写移位硬编码。
- 易错：用 `char` 指针看首字节前必须转成 `unsigned char *`，否则可能被当成负数。

### Q50 位操作：置位、清位、统计 1 的个数？
**答**：
- 位操作三件套加一个 `popcount`，注意用 `1u` 保证无符号、移位数必须小于类型位宽。

```c
#define BIT_SET(x, n)   ((x) |=  (1u << (n)))
#define BIT_CLR(x, n)   ((x) &= ~(1u << (n)))
#define BIT_TST(x, n)   (((x) >> (n)) & 1u)
#define BIT_FLIP(x, n)  ((x) ^=  (1u << (n)))

int popcount(unsigned int x)
{
    int n = 0;

    while (x != 0) {
        x &= x - 1;        /* 每次清掉最低位的 1 */
        n++;
    }
    return n;
}
```

- 要点：清位是 `&= ~(1u << n)` 而不是 `&= (0u << n)`；移位超过位宽是 UB；宏参数全部加括号。
- 延伸：`x & (x - 1)` 还能判 2 的幂（`x && !(x & (x - 1))`）；GCC 有 `__builtin_popcount`，CPU 有 POPCNT 指令。

## 面试节奏建议

1. **先给结论，再展开**：第一句就把判断说出来（"这是 UB，因为缺序列点"），然后补原因和例子；面试官考的是判断力，不是背课文。
2. **主动说边界和代价**：每个方案都配一句"代价是什么"——对齐省时间费空间、内联省调用费体积、`volatile` 不保证原子性。
3. **不会时给思路而不是硬编**：说清"我会先确认标准怎么规定，再写最小复现用 ASan 验证"，比编一个错答案体面得多。
4. **手写代码先说接口契约**：返回值、谁负责 `free`、能不能重叠、长度含不含 `'\0'`，边说边写，比闷头写完再解释强。
5. **留一个钩子收尾**：答完补一句延伸（"再往下就是编译器的优化边界"），把话题引到自己熟的方向。

> 全部 50 题建议分三次过：第一遍只答结论，第二遍补边界，第三遍限时手写 Q44–Q50。
