## 1 CPU 的功能与组成

### 1.1 CPU 的功能

CPU（中央处理器）= 运算器 + 控制器，是计算机的「大脑」，主要功能：

* **指令控制**：按程序顺序取指令、执行指令，保证指令流的顺序性（PC 的作用）。
* **操作控制**：把指令翻译成一系列控制信号，控制各部件协同动作。
* **时间控制**：对各种操作实施定时，用时钟周期（节拍）统一节奏。
* **数据加工**：对数据进行算术运算和逻辑运算（ALU 的作用）。
* **中断处理**：响应外部中断与内部异常，保护现场并转去处理。

### 1.2 运算器的组成

| 部件 | 作用 |
| --- | --- |
| ALU 算术逻辑单元 | 完成算术、逻辑、移位等运算 |
| ACC 累加器 | 存放被加数、被乘数、运算结果 |
| MQ 乘商寄存器 | 乘法存乘数 / 乘积低位，除法存商 |
| X 操作数寄存器 | 存放另一个操作数 |
| PSW 程序状态字 | 存放进位、溢出、零、符号等标志与中断允许位 |
| 通用寄存器组 | 存放操作数、指针、中间结果，减少访存 |
| 移位器 | 完成算术/逻辑移位、循环移位 |

### 1.3 控制器的组成

| 部件 | 作用 |
| --- | --- |
| PC 程序计数器 | 存放当前指令地址（或下一条），可自动加「1」或接收转移地址 |
| IR 指令寄存器 | 存放当前正在执行的指令，OP 字段送 CU 译码 |
| ID 指令译码器 | 对操作码译码，产生相应控制信号 |
| CU 控制单元 | 产生全部微操作控制信号（硬布线或微程序实现） |
| 时序系统 | 产生时钟、节拍、机器周期等定时信号 |

### 1.4 寄存器小结（易混点）

| 寄存器 | 归属 | 对程序员是否可见 | 说明 |
| --- | --- | --- | --- |
| PC | 控制器 | 可见 | 转移指令可修改，取指后自动加 1（指令字长） |
| IR | 控制器 | **不可见** | 完全由硬件使用，程序无法直接访问 |
| MAR | 主存接口 | 不可见 | 地址寄存器，位数决定寻址空间 |
| MDR | 主存接口 | 不可见 | 数据寄存器，位数 = 存储字长 |
| PSW | 运算器 | 可见（部分） | 条件转移依赖其标志位 |
| 通用寄存器 | 运算器 | 可见 | 由指令中的寄存器号指定 |

## 2 数据通路

### 2.1 数据通路与单总线结构

**数据通路**：CPU 内部各部件之间传送数据的路径（连线 + 总线 + 多路选择器 + 暂存器）。

单总线结构：所有部件（寄存器、ALU、MAR、MDR）都挂在一条内部总线上，同一时刻总线上只能有一个数据在传送，因此一个微操作序列必须串行完成。

单总线的两个代价：

1. **一次只能传一个数据**，ALU 的两个操作数要分两次送入（因此需要 Y、Z 两个暂存器）。
2. 容易出现总线竞争，需要多路选择器与三态门控制。

### 2.2 单总线上的微操作序列

```text
取指周期： (PC)→MAR, M(MAR)→MDR, (MDR)→IR, (PC)+1→PC, OP(IR)→CU
ADD R0, R1：(R0)→Y, (Y)+(R1)→Z, (Z)→R0          ; R0 ← R0 + R1
LOAD R1,(A)：(A)→MAR, M(MAR)→MDR, (MDR)→R1       ; R1 ← (A)
```

其中 Y、Z 是 ALU 输入/输出的暂存器：单总线一次只送一个操作数，必须先把第一个操作数锁存到 Y，再让第二个操作数上总线。

### 2.3 多总线与专用数据通路

* 双总线 / 三总线结构：ALU 两个输入端各有一条总线，一次即可取两个操作数，微操作数减少、速度提高，但总线占用芯片面积。
* 专用数据通路（RISC 常用）：寄存器堆有独立读端口，ALU 结果经专用通路直接写回，配合流水线寄存器实现每周期一条指令。

## 3 控制器

### 3.1 硬布线控制器

用组合逻辑电路（门电路）直接产生控制信号，输入是操作码、时序信号、状态标志。

* 设计步骤：列微操作序列 → 写出每个控制信号的逻辑表达式 → 化简 → 用门电路实现。
* 优点：速度快（纯硬件延迟），适合 RISC 与流水线。
* 缺点：设计复杂、修改困难（指令系统一变就要重新设计电路），不灵活。

### 3.2 微程序控制器

**核心思想**：把每条机器指令的微操作序列编成微程序，存放在控制存储器（CM）中，执行指令就是逐条取出微指令。

| 术语 | 含义 |
| --- | --- |
| 微命令 | 控制部件发出的最小控制信号（如 PC→MAR） |
| 微操作 | 微命令对应的最小操作 |
| 微指令 | 若干微命令的组合 + 下地址信息，是 CM 的一个存储单元 |
| 微程序 | 完成一条机器指令的全部微指令序列 |
| 控制存储器 CM | 存放全部微程序，只读，属控制器内部 |
| μPC / μMAR | 微地址寄存器，指向下一条微指令 |
| 微周期 | 执行一条微指令所需的时间 |

对应关系：**一条机器指令 ⇔ 一个微程序；一条微指令 ⇔ 一个微周期；一条微命令 ⇔ 一个微操作**。

### 3.3 微指令的编码方式

| 方式 | 做法 | 位数 | 并行性 | 说明 |
| --- | --- | --- | --- | --- |
| 直接编码（水平） | 每个微命令占 1 位，1 表示有效 | 最多 | 最高，一次可执行全部微命令 | 速度最快，但微指令过长 |
| 字段直接编码 | 把互斥的微命令分成若干字段，字段译码后产生微命令 | 少 | 较高 | 每字段要留一个「不操作」编码，字段长度 = ⌈log2(组内微命令数 + 1)⌉ |
| 字段间接编码 | 某字段的含义由另一字段解释 | 更少 | 低 | 进一步压缩位数，译码级数增加、速度变慢 |

**例** 某机有 40 个微命令，采用字段直接编码，把它们分成 5 组、每组 8 个互斥微命令，求微指令的操作控制字段至少多少位？

```text
每组：8 个微命令 + 1 个「不操作」状态 = 9 种状态
每组需要 ⌈log2 9⌉ = 4 位
操作控制字段共 5 × 4 = 20 位

对比：直接编码需要 40 位，字段直接编码压缩到 20 位，节省一半。
```

### 3.4 微指令格式与下地址形成

| 格式 | 特点 |
| --- | --- |
| 水平型微指令 | 一次可定义并执行多个微命令，微指令长、微程序短、并行性高 |
| 垂直型微指令 | 类似机器指令，一次只能完成一个微操作，微指令短、微程序长、并行性低 |

下地址（确定下一条微指令地址）的方式：

* **计数器方式**：微程序顺序存放，μPC 自动加 1；遇转移时由微指令给出转移地址。控制简单，但微程序不能随意安排位置。
* **断定方式**：由微指令的下地址字段直接给出后继微地址，可任意安排、便于分支，但微指令多一个字段。
* 实际机器常把两种方式结合（顺序用计数器，分支用下地址字段）。

### 3.5 硬布线与微程序对比

| 对比项 | 硬布线控制器 | 微程序控制器 |
| --- | --- | --- |
| 控制信号产生 | 组合逻辑电路 | 从 CM 取微指令，经译码产生 |
| 速度 | 快 | 慢（多一次访存 CM，通常 CM 用高速 ROM） |
| 设计难度 | 复杂、周期长 | 规整、易于设计 |
| 可修改性 | 差（改指令要改电路） | 好（改微程序即可） |
| 芯片面积 | 大（随机逻辑） | 小（规整的 ROM 阵列） |
| 适用 | RISC、流水线 CPU | CISC、指令复杂的机器 |

## 4 指令执行过程

### 4.1 指令周期

指令周期 = 取指周期 +（间址周期）+ 执行周期 +（中断周期），每个周期由若干机器周期（节拍）组成。

* **取指周期**：所有指令都必须有。
* **间址周期**：只有间接寻址的指令才有。
* **执行周期**：按操作码完成实际功能。
* **中断周期**：有中断请求且允许中断时才有。

### 4.2 各周期的数据流

取指周期：

```text
(PC) → MAR → M → MDR → IR，同时 (PC) + 1 → PC
OP(IR) → CU
```

间址周期（以一次间接寻址为例）：

```text
Ad(IR) → MAR → M → MDR → Ad(IR)（用读出的内容替换形式地址，得到有效地址）
```

执行周期（以 `ADD R1, (A)` 为例）：

```text
Ad(IR) → MAR → M → MDR
(MDR) + (R1) → R1
```

中断周期（由**中断隐指令**完成，不是真正的指令）：

```text
① 关中断：把中断允许触发器清 0，防止保存现场时被新中断打断
② 保存断点：把 PC 内容存入主存特定单元或压入堆栈
③ 引出中断服务程序：形成中断服务程序的入口地址送 PC（中断向量）
```

### 4.3 指令执行方案

| 方案 | 做法 | 特点 |
| --- | --- | --- |
| 单周期 | 每条指令一个时钟周期 | 周期长（取最慢指令），硬件重复浪费 |
| 多周期 | 一条指令分多个机器周期，不同指令周期数不同 | 硬件复用、效率提高，控制复杂 |
| 流水线 | 多条指令的不同阶段重叠执行 | 吞吐率最高，需处理冒险 |

## 5 指令流水线

### 5.1 五段流水线

```text
IF → ID → EX → MEM → WB
```

各段由流水线寄存器（锁存器）隔开，每段在一个时钟周期内完成，时钟周期取最慢段的时间（含锁存器延迟）。

### 5.2 性能计算与例题

设流水线 k 段、每段用时 Δt、连续执行 n 条指令：

```text
总时间    T = (k + n - 1) × Δt
吞吐率    TP = n / ((k + n - 1) × Δt)
加速比    S = n × k × Δt / T = n × k / (k + n - 1)
效率      E = S / k = n / (k + n - 1)
```

**例** 某 5 段流水线，每段耗时 1 ns（含锁存器），连续执行 100 条指令。求总时间、吞吐率、加速比和效率；若不用流水线（串行执行）需要多久？

```text
① 总时间 T = (k + n - 1) × Δt = (5 + 100 - 1) × 1 ns = 104 ns

② 吞吐率 TP = n / T = 100 / 104 ns ≈ 0.9615 条/ns ≈ 961.5 条/μs（即约 962 MIPS）

③ 串行执行时间 T' = n × k × Δt = 100 × 5 × 1 = 500 ns
   加速比 S = T' / T = 500 / 104 ≈ 4.81

④ 效率 E = S / k = 4.81 / 5 ≈ 96.2%，也可直接用 n / (k + n - 1) = 100 / 104 ≈ 96.2%

⑤ 理论上限：n → ∞ 时 S → k = 5，E → 100%，TP → 1 条/ns
```

若时钟周期因锁存器开销变为 1.2 ns，则 T = 104 × 1.2 = 124.8 ns，加速比降为 500 / 124.8 ≈ 4.01，说明**锁存器开销与段间不均衡会显著侵蚀流水线收益**。

### 5.3 流水线冒险（相关）与解决

| 类型 | 成因 | 表现 | 解决方法 |
| --- | --- | --- | --- |
| 结构冒险（资源冲突） | 多条指令同时争用同一硬件 | 如 IF 与 MEM 同时访存 | 停顿（stall）、指令 Cache 与数据 Cache 分离、增设部件 |
| 数据冒险 | 后一条指令用到前一条还没写回的结果（主要是 RAW） | 读到旧值 | 数据转发（旁路）、编译器调度插入无关指令、停顿 |
| 控制冒险 | 转移指令改变 PC，已取的指令作废 | 取到错误指令 | 分支预测、延迟转移（延迟槽）、提前在 ID 段判断转移、预取 |

**数据冒险示例**：

```text
I1: ADD R1, R2, R3     ; EX 段末尾才得到 R1
I2: SUB R4, R1, R5     ; ID 段就要读 R1 → 数据冒险

解决：把 EX 段的结果直接转发到 ALU 输入端（EX→EX 转发），不必等 WB 写回；
      若 I1 是 LOAD R1, (R2)，数据要到 MEM 段末尾才有，此时必须停顿 1 个周期（load-use 冒险）。
```

**控制冒险示例**：条件转移在 EX 段才确定方向，此时已取入后两条指令，需冲刷（flush）2 条；若把转移判断提前到 ID 段，只需冲刷 1 条。

### 5.4 提高流水线性能的技术

* **超标量**：每个时钟周期发射多条指令（多条流水线并行），依赖指令级并行。
* **超流水线**：把每段再细分，提高时钟频率，段数更多、开销更大。
* **超长指令字 VLIW**：由编译器把多条可并行操作打包成一条长指令，硬件简单，依赖编译器。
* 其他：动态调度（乱序执行）、寄存器重命名、推测执行。

## 6 多处理器

### 6.1 Flynn 分类

| 类别 | 含义 | 典型结构 |
| --- | --- | --- |
| SISD | 单指令流单数据流 | 传统冯·诺依曼单处理器 |
| SIMD | 单指令流多数据流 | 向量处理器、阵列处理器、GPU 的 SIMT |
| MISD | 多指令流单数据流 | 实际中几乎不存在（流水线有时被勉强归入） |
| MIMD | 多指令流多数据流 | 多核处理器、多处理器系统、集群 |

### 6.2 多核与硬件多线程

* **多核处理器**：一个芯片上集成多个完整的处理器核，每核有私有 L1/L2 Cache，共享 L3 Cache 与内存控制器。
* **硬件多线程**：一个核上用多组寄存器保存多个线程的上下文，切换开销极小。
  * 细粒度多线程：每个时钟周期轮换线程（可掩盖短停顿）。
  * 粗粒度多线程：只在发生长停顿时切换（如 Cache 缺失）。
  * 同时多线程 SMT（超线程）：同一周期内发射多个线程的指令，共享执行单元。

### 6.3 共享内存与消息传递

| 模型 | 通信方式 | 特点 |
| --- | --- | --- |
| 共享内存（多处理器） | 读写同一地址空间 | 编程简单，需缓存一致性协议 |
| 消息传递（多计算机） | 显式发送/接收消息 | 可扩展性好，编程复杂 |

共享内存按访问时间又分：

* **UMA**（均匀访存）：所有处理器访存时间相同，总线或交叉开关连接，规模受限。
* **NUMA**（非均匀访存）：每个处理器有本地内存，访问本地快、访问远程慢，可扩展性好。

多核共享内存必须保证**缓存一致性**：常用监听式协议（MESI：Modified / Exclusive / Shared / Invalid），写共享数据时使其他核的副本失效。

## 7 常考题型小结

* CPU 组成：分清哪些寄存器在运算器、哪些在控制器；IR、MAR、MDR 对程序员不可见，PC、通用寄存器、PSW 可见。
* 数据通路：给定单总线结构，写出取指、间址、执行某指令的微操作序列；注意 ALU 两操作数要分两次上总线。
* 控制器：硬布线与微程序的对比；微指令编码位数计算（字段直接编码要留「不操作」码）。
* 指令周期：四个周期的数据流；中断隐指令的三件事（关中断、保存断点、引出中断服务程序）。
* 流水线：T、TP、S、E 四个公式必须能默写并代入计算；注意 n → ∞ 的极限结论。
* 流水线冒险：区分结构 / 数据 / 控制相关，能说出各自 2~3 种解决办法，能判断 load-use 需要停顿几拍。
* 多处理器：Flynn 四分类的代表系统；UMA 与 NUMA 的区别；缓存一致性的必要性。
