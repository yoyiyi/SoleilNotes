## 1 I/O 系统概述

### 1.1 I/O 系统的组成

I/O 系统由**软件**与**硬件**两部分组成，目标是「让 CPU 尽量少干预、让设备与主机并行工作」。

| 层次 | 内容 |
| --- | --- |
| 用户层 I/O 软件 | 库函数（如 C 的 `fread`）、假脱机系统 |
| 设备无关的 OS 软件 | 缓冲管理、设备分配、错误处理、逻辑设备名到物理设备的映射 |
| 设备驱动程序 | 把抽象 I/O 请求翻译成设备能识别的命令（与硬件直接相关） |
| 中断处理程序 | 处理设备完成/出错的中断 |
| I/O 硬件 | 设备、设备控制器（I/O 接口）、I/O 总线 |

### 1.2 I/O 接口的功能

* **地址译码与设备选择**：接收 CPU 发来的地址，选中相应接口与端口。
* **数据缓冲**：用数据寄存器/缓冲器匹配 CPU 与设备的速度差异。
* **数据格式转换**：串行 ↔ 并行、电平转换、模数/数模转换。
* **通信与同步**：与设备按协议握手（如 ready/ack 信号）。
* **状态报告**：向 CPU 提供设备状态（忙、就绪、出错）。
* **控制与定时**：接受 CPU 的控制命令，控制设备动作。
* **中断与 DMA 控制**：产生中断请求，或在 DMA 方式下直接控制数据传送。

### 1.3 I/O 接口的组成与端口

接口内部通常有三类**端口**（端口就是接口内可被 CPU 访问的寄存器）：

| 端口 | 方向 | 作用 |
| --- | --- | --- |
| 数据端口 | 双向 | 暂存待传送的数据，起缓冲作用 |
| 状态端口 | 只读 | 提供设备与接口的状态（就绪、忙、错误） |
| 控制端口 | 只写 | 接收 CPU 的命令（启动、复位、设置工作方式） |

一个接口可以有多个数据端口和多个状态/控制端口，因此「接口」不等于「端口」：接口是硬件的整体，端口是其中可编址的寄存器。

### 1.4 I/O 编址方式

| 对比项 | 统一编址（存储器映射 I/O） | 独立编址（I/O 映射 I/O） |
| --- | --- | --- |
| 地址空间 | 与主存共用同一地址空间 | 独立的 I/O 地址空间 |
| 访问指令 | 用普通的访存指令（LOAD/STORE） | 专用 I/O 指令（IN/OUT） |
| 地址译码 | 简单（一套译码器） | 需要区分访存与 I/O 周期 |
| 寻址范围 | 占用主存地址空间 | 不占用主存空间 |
| 程序可读性 | 像访问内存一样，编程灵活 | 指令语义清晰，易区分 |
| 典型例子 | ARM、RISC-V 的 MMIO | x86 的 IN/OUT |

## 2 I/O 方式

### 2.1 程序查询方式（程序控制方式）

流程：CPU 不断读取设备状态端口 → 判断是否就绪 → 未就绪则继续查询（原地循环）→ 就绪则传送一个数据 → 修改地址与计数器 → 判断是否传送完毕。

```text
while (1) {
    读状态端口；
    if (就绪)  {  读/写数据端口； 地址+1； 计数-1； }
    if (计数 == 0) break;
}
```

* 优点：硬件简单，不需要中断机构。
* 缺点：**CPU 与设备串行工作**，CPU 在等待期间只能空转（或轮询），效率极低；且无法及时发现故障。
* 改进：定时查询（每隔固定时间查一次），可在等待间隙做其他工作，但响应变慢。

**例** 某设备的数据传输率为 1 MB/s，CPU 主频 1 GHz，查询并传送一个字节平均需要 50 个时钟周期，若采用程序查询方式，CPU 的时间开销比例是多少？

```text
① 设备每传送 1 字节所需时间 = 1 B / 1 MB/s = 1 μs
② CPU 处理 1 字节所需时间 = 50 个时钟周期 × (1 / 1 GHz) = 50 ns = 0.05 μs
③ 若 CPU 一直轮询，则 1 μs 内 CPU 全部被占用 → 开销 100%
   若「定时查询」，每 1 μs 查一次即够用，则开销 ≈ 0.05 μs / 1 μs = 5%
```

结论：程序查询方式只适合设备很少、速度极慢或对实时性要求不高的场合。

### 2.2 程序中断方式

**基本思想**：CPU 启动设备后继续执行原程序；设备就绪时向 CPU 发中断请求，CPU 在**当前指令执行结束后**响应，转去执行中断服务程序完成一个数据的传送，然后返回原程序。

#### 2.2.1 中断的分类

| 类别 | 来源 | 例子 | 是否可屏蔽 |
| --- | --- | --- | --- |
| 外中断（中断） | CPU 外部 | I/O 设备、时钟、键盘 | 可屏蔽中断可被 IF 屏蔽，不可屏蔽中断（NMI）不能 |
| 内中断（异常） | CPU 内部、与当前指令有关 | 缺页、除零、溢出、断点、系统调用 | 通常不可屏蔽 |

#### 2.2.2 中断处理流程

```text
① 中断请求：设备通过 INTR 线发出请求，置位接口中的中断请求触发器
② 中断判优：多个请求同时到达时按优先级排队（硬件排队器或软件查询）
③ 中断响应：满足「有请求 + CPU 开中断 + 当前指令执行完」后响应
   响应时由【中断隐指令】完成三件事（硬件自动完成，不是程序指令）：
     · 关中断
     · 保存断点（PC 入栈或存入指定单元）
     · 引出中断服务程序（中断向量 → PC）
④ 中断服务：
     · 保护现场（保存通用寄存器、PSW）
     · 开中断（允许更高级中断嵌套，即多重中断）
     · 执行设备服务程序（传送数据）
     · 关中断
     · 恢复现场
     · 开中断
     · 中断返回（恢复 PC）
⑤ 中断返回：返回被中断的程序继续执行
```

#### 2.2.3 多重中断与中断屏蔽字

* 多重中断（中断嵌套）：CPU 在执行中断服务程序时，若开中断且来了更高优先级的中断，可以再次响应。
* 实现条件：**在服务程序中提前开中断**，并用**中断屏蔽字**控制哪些中断可以被响应。
* 屏蔽字：每个中断源对应一个屏蔽字，位数为中断源个数；某位为 1 表示屏蔽该中断源，为 0 表示允许。
  处理某级中断时，屏蔽字中「优先级不高于自己」的位都置 1，「优先级高于自己」的位清 0。

**例** 4 个中断源 A、B、C、D，硬件优先级 A > B > C > D，写出各中断源的中断屏蔽字（列顺序 A B C D）。

| 正在处理 | 屏蔽字 A B C D | 说明 |
| --- | --- | --- |
| A | 1 1 1 1 | A 最高，屏蔽自己及所有更低级，不允许被嵌套 |
| B | 0 1 1 1 | 允许 A 打断，屏蔽 B、C、D |
| C | 0 0 1 1 | 允许 A、B 打断 |
| D | 0 0 0 1 | 允许 A、B、C 打断 |

#### 2.2.4 中断向量

* 中断向量：中断服务程序的入口地址。
* 中断向量表：所有中断向量集中存放的表格，放在主存固定区域；中断源编号（中断类型号）作为索引。
* 向量中断：由硬件根据中断类型号自动查表得到入口地址，速度快；非向量中断则由软件查询确定入口。

**例** 某系统每秒产生 2000 次设备中断，每次中断的响应与服务（含保护/恢复现场）共需 200 个时钟周期，CPU 主频 2 GHz。求 CPU 用于该设备 I/O 的时间比例。

```text
① 每次中断开销 = 200 × (1 / 2 GHz) = 200 × 0.5 ns = 100 ns
② 每秒中断总开销 = 2000 × 100 ns = 200 μs
③ 比例 = 200 μs / 1 s = 0.02%
```

可以看出：中断方式下 CPU 开销与**中断次数**成正比，适合低速、随机出现的 I/O。

### 2.3 DMA 方式

**基本思想**：由 DMA 控制器（DMAC）直接控制设备与主存之间的数据块传送，传送过程不经过 CPU，CPU 只在传送前初始化、传送后被中断告知。

#### 2.3.1 DMA 控制器的组成

| 部件 | 作用 |
| --- | --- |
| 主存地址寄存器 AR | 存放要交换数据的主存地址，每传送一个数据自动加 1 |
| 字计数器 WC | 记录剩余传送个数，每传送一个减 1，为 0 时发结束信号 |
| 数据缓冲寄存器 | 暂存每次传送的数据 |
| 设备地址寄存器 | 指明本次传送的设备 |
| 控制/状态逻辑 | 产生 DMA 请求、总线请求，控制传送时序 |
| 中断机构 | 传送结束后向 CPU 发中断，做后处理 |

#### 2.3.2 DMA 的三种工作方式（总线使用权）

| 方式 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 停止 CPU 访存 | DMA 传送期间 CPU 放弃总线，暂停访存 | 控制简单，传送速度快 | CPU 在整块传送期间不能访存，效率低 |
| 周期挪用（周期窃取） | DMA 每传送一个数据就「借用」一个存储周期，用完立即还给 CPU | CPU 与 DMA 交替访存，兼顾效率 | 每次都要申请/归还总线，控制稍复杂 |
| DMA 与 CPU 交替访存 | 把时间划分成固定时间片，DMA 与 CPU 轮流使用总线 | 无需总线申请，效率高 | 时间片划分固定，灵活性差 |

周期挪用方式下，DMA 请求的优先级**高于 CPU**：因为设备的数据若不及取走就会丢失，而 CPU 晚一个周期访存只影响速度。

#### 2.3.3 DMA 的传送过程

```text
① 预处理：CPU 初始化 DMAC（主存地址、传送长度、设备地址、方向、启动）
② 数据传送：设备 → DMAC → 主存（或反向），每传送一个数据 AR+1、WC-1
③ 后处理：WC 为 0 时 DMAC 发中断，CPU 校验数据、决定是否继续
```

#### 2.3.4 DMA 与中断的对比

| 对比项 | 程序中断方式 | DMA 方式 |
| --- | --- | --- |
| 数据传送的执行者 | CPU 执行程序完成 | DMA 控制器硬件完成 |
| 响应时机 | 一条指令执行结束后 | 每个存储周期结束后（可随时响应） |
| 传送单位 | 字节或字 | 数据块 |
| 数据流向 | 设备 ↔ CPU 寄存器 ↔ 主存 | 设备 ↔ 主存（不经过 CPU） |
| 优先级 | 低于 DMA | 高于中断 |
| CPU 开销 | 每次都要保存/恢复现场 | 只需预处理和后处理 |
| 适用场合 | 低速、随机 I/O | 高速、成块 I/O（磁盘、网卡、显卡） |

**例** 某磁盘传输率为 4 MB/s，采用 DMA 方式，每次 DMA 传送 4 个字节，DMA 占用总线 0.2 μs。求 DMA 占用总线的时间比例。

```text
① 每传送 4 B 所需时间 = 4 B / 4 MB/s = 1 μs
② DMA 占用总线 0.2 μs，故占用比例 = 0.2 / 1 = 20%
③ 剩余 80% 的总线时间可供 CPU 访存
```

## 3 磁盘

### 3.1 磁盘的结构

* 盘片、盘面（记录面）、磁头（每个记录面一个）、磁道（同心圆）、扇区（磁道上的等长弧段）。
* **柱面**：所有盘面上半径相同的磁道构成的集合；按柱面存取可减少寻道次数。
* 磁盘地址一般由「柱面号（磁道号）+ 盘面号（磁头号）+ 扇区号」组成。

### 3.2 容量计算

```text
磁盘容量 = 记录面数 × 每面磁道数 × 每道扇区数 × 扇区容量
```

**例** 某磁盘有 8 个记录面，每面 1024 个磁道，每道 64 个扇区，每扇区 512 B。求容量，并给出磁盘地址格式。

```text
① 容量 = 8 × 1024 × 64 × 512 B
       = 8 × 1024 × 32768 B
       = 268 435 456 B = 256 MB

② 每个记录面容量 = 1024 × 64 × 512 B = 32 MB

③ 地址位数：盘面号 8 面 → 3 位；柱面号 1024 → 10 位；扇区号 64 → 6 位
   共 19 位
```

### 3.3 存取时间

```text
存取时间 T = 平均寻道时间 + 平均旋转延迟 + 传输时间
平均旋转延迟 = 旋转一周的时间 / 2 = 60 / (2 × 转速 r/min) 秒
传输时间 = 要传送的字节数 / 数据传输率
数据传输率 = 每道容量 × 每秒转数
```

**例** 上例磁盘转速为 7200 r/min，平均寻道时间 8 ms。求读取一个扇区（512 B）的平均存取时间与数据传输率。

```text
① 转速 7200 r/min = 120 r/s，旋转一周 = 1/120 s ≈ 8.33 ms
   平均旋转延迟 = 8.33 / 2 ≈ 4.17 ms

② 数据传输率 = 每道容量 × 每秒转数 = 64 × 512 B × 120 = 3 932 160 B/s ≈ 3.93 MB/s

③ 传输一个扇区的时间 = 512 B / 3 932 160 B/s ≈ 0.13 ms

④ 平均存取时间 = 8 ms + 4.17 ms + 0.13 ms ≈ 12.3 ms
```

### 3.4 磁盘调度

| 算法 | 思想 | 特点 |
| --- | --- | --- |
| FCFS | 按请求到达顺序服务 | 公平、简单，平均寻道时间长 |
| SSTF | 优先服务离当前磁头最近的请求 | 平均寻道时间短，可能「饥饿」远端请求 |
| SCAN（电梯） | 沿一个方向扫描，沿途服务，到边界再反向 | 无饥饿，平均寻道较好 |
| C-SCAN | 只在一个方向服务，返回时快速回扫不服务 | 更公平，两端请求等待时间均衡 |

## 4 RAID

RAID 用多块廉价磁盘组成阵列，通过**条带化**提高并行性（性能），通过**冗余**提高可靠性。

| 级别 | 技术 | 最少磁盘数 | 容量利用率 | 容错能力 | 说明 |
| --- | --- | --- | --- | --- | --- |
| RAID 0 | 条带化，无冗余 | 2 | 100% | **无**，坏一块即全毁 | 读写并行度最高，用于临时数据 |
| RAID 1 | 镜像，两份相同数据 | 2 | 50% | 每组可坏 1 块 | 读性能好，写要写两份，成本高 |
| RAID 5 | 条带化 + 分布式奇偶校验 | 3 | (n-1)/n | 可坏 1 块 | 校验分散在各盘，无专门校验盘瓶颈 |
| RAID 10 | 先镜像再条带（1+0） | 4 | 50% | 每组可坏 1 块 | 性能与可靠性兼顾，成本高 |

要点：

* RAID 0 只提高性能、不提高可靠性；RAID 1/5 提高可靠性；RAID 5 的写操作需要「读旧数据 + 读旧校验 + 写新数据 + 写新校验」，写代价较大。
* RAID 5 的容量 = (磁盘数 - 1) × 单盘容量；RAID 1 的容量 = 磁盘数 / 2 × 单盘容量。
* 提高磁盘 I/O 速度的其他手段：磁盘缓存、提前读、延迟写、优化物理块分布（交替编号、错位命名）、并行交叉存取。

## 5 常考题型小结

* 接口与端口：区分接口与端口，记住数据/状态/控制三类端口的方向与作用。
* 编址方式：统一编址与独立编址的对比（地址空间、访问指令、优缺点），能判断给定机器属于哪种。
* 程序查询：会算 CPU 开销比例；结论是 CPU 与设备串行、效率最低。
* 中断：能默写中断处理流程与中断隐指令的三件事；会按优先级写中断屏蔽字；理解多重中断的条件。
* DMA：三种工作方式（停止 CPU 访存、周期挪用、交替访存）的取舍；与中断方式的 7 项对比；会算 DMA 占用总线比例。
* 磁盘：容量、地址位数、平均旋转延迟、传输率、平均存取时间的公式与计算。
* RAID：RAID 0/1/5（含 10）的冗余方式、最少盘数、容量利用率与容错能力。
