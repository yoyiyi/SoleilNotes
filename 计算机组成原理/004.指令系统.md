## 1 指令系统概述

### 1.1 指令与指令系统

* **指令**：计算机执行某种操作的命令，是硬件与软件之间的接口。
* **指令系统（指令集）**：一台计算机全部指令的集合，决定了机器的基本功能，是汇编语言与编译器的目标。
* 指令系统的两个基本要求：**完备性**（常用功能都有对应指令）与**有效性**（程序高效、指令格式规整）。

### 1.2 指令的基本格式

一条指令通常由**操作码**和**地址码**两部分组成：

```text
操作码 OP | 地址码 A1 | A2 | A3 | ...
```

* 操作码：指明做什么操作（加、减、传送、转移等），长度决定指令条数上限。
* 地址码：给出操作数地址或操作数本身，个数决定指令的「地址数」。

### 1.3 指令字长

* 指令字长：一条指令包含的二进制位数。它与机器字长、存储字长可以不同。
* **定长指令字**：所有指令长度相同，取指简单、便于流水线，RISC 常用。
* **变长指令字**：常用指令短、不常用指令长，节省存储空间，CISC 常用；代价是取指与译码复杂。
* 指令字长一般是字节的整数倍，按字节编址时要求「按边界对齐」可提高取指效率。

### 1.4 按地址码个数分类

| 类型 | 格式 | 含义 | 典型用途 |
| --- | --- | --- | --- |
| 零地址 | OP | 无地址码 | 空操作 NOP、停机、堆栈运算（操作数隐含在栈顶） |
| 一地址 | OP A1 | 单操作数，或隐含另一个操作数 | 取反、加 1、`ACC ← ACC + A1` |
| 二地址 | OP A1 A2 | 双操作数 | `A1 ← A1 OP A2`，结果放 A1（目的地址） |
| 三地址 | OP A1 A2 A3 | 双操作数 + 结果地址 | `A3 ← A1 OP A2`，不破坏源操作数 |
| 四地址 | OP A1 A2 A3 A4 | 增加下一条指令地址 | 早期机器，现代由 PC 取代 |

结论：地址码越多，程序越短但指令越长；现代机器多用二地址（寄存器型）或三地址（RISC）。

### 1.5 操作码的两种组织方式

* **定长操作码**：操作码位数固定，译码简单、速度快，但指令条数受限（n 位最多 2^n 条）。
* **变长操作码（扩展操作码）**：操作码长度随指令变化，用较少位数表示常用指令，兼顾指令条数与指令字长。

## 2 扩展操作码

### 2.1 设计原则

在指令字长固定的前提下，把地址码字段按需「借」给操作码使用：

1. 使用频率高的指令分配短操作码，频率低的分配长操作码（类似 Huffman 的思想）。
2. **短操作码不能是长操作码的前缀**，否则译码时无法判断操作码长度，产生歧义。
3. 每一级都要为下一级留下若干个编码作为扩展标志。

### 2.2 例题：判断指令条数是否可行

**例 1** 某机指令字长 16 位，由 4 位操作码 OP 和 3 个 4 位地址码 A1、A2、A3 组成。要求设计：三地址指令 15 条、二地址指令 12 条、一地址指令 60 条、零地址指令 32 条。问是否可行？给出编码方案。

```text
① 三地址：OP 共 4 位，有 16 种编码
   用 0000 ~ 1110 共 15 条，剩下 1111 作为扩展标志

② 二地址：操作码扩为 8 位（1111 + A1 字段 4 位），共 16 种
   用 12 条（1111 0000 ~ 1111 1011），剩 4 个（1111 1100 ~ 1111 1111）作扩展

③ 一地址：操作码扩为 12 位，共 4 × 16 = 64 种
   用 60 条，剩 4 个作扩展

④ 零地址：操作码扩为 16 位，共 4 × 16 = 64 种 ≥ 32，够用

结论：可行。三地址 15 条、二地址 12 条、一地址 60 条、零地址 32 条可以共存。
```

**例 2** 同上指令格式，若三地址指令需要 8 条、二地址指令需要 8 条，则一地址指令最多可有多少条（不再保留零地址指令）？

```text
① 三地址用掉 8 个编码，剩 8 个扩展标志
② 二地址可用 8 × 16 = 128 种，用掉 8 种，剩 120 个扩展标志
③ 一地址最多 120 × 16 = 1920 条
```

记忆口诀：**每剩下一个扩展标志，下一级就多 16 个编码**；反之，若下一级需要 m 条指令，就至少占用 ceil(m / 16) 个上级扩展标志。

## 3 寻址方式

### 3.1 指令寻址

* **顺序寻址**：PC 自动加「指令字长」，形成下一条指令地址。
* **跳跃寻址**：由转移指令给出目标地址，直接修改 PC；相对转移依赖当前 PC 值。

### 3.2 数据寻址方式

设指令中的形式地址为 A，寄存器内容用 (R) 表示，存储单元内容用 (A) 表示。

| 寻址方式 | 有效地址 EA 或操作数 | 取操作数访存次数 | 特点与用途 |
| --- | --- | --- | --- |
| 立即寻址 | 操作数 = A，A 即操作数本身 | 0 | 速度最快，但操作数大小受地址码字段位数限制 |
| 直接寻址 | EA = A | 1 | 简单直观，寻址范围受地址码位数限制 |
| 间接寻址 | EA = (A) | 2（多级间址更多） | 扩大寻址范围，可实现多级间址，但访存次数多 |
| 寄存器寻址 | 操作数 = (R)，EA 即寄存器 | 0 | 速度快、指令短，受寄存器数量限制 |
| 寄存器间接寻址 | EA = (R) | 1 | 寻址范围取决于寄存器位数，比存储器间址快 |
| 相对寻址 | EA = (PC) + A | 1 | A 为补码位移量，用于转移指令，便于程序浮动 |
| 基址寻址 | EA = (BR) + A | 1 | 面向系统，用于多道程序重定位，BR 由操作系统设定 |
| 变址寻址 | EA = (IX) + A | 1 | 面向用户，用于数组、循环处理，IX 由用户改变 |
| 堆栈寻址 | EA = (SP)，SP 自动增减 | 1 | 用于子程序调用、中断、表达式求值 |

几点必须分清：

* 立即寻址、寄存器寻址**不需要访存取操作数**（取指时已把操作数或寄存器号取到）。
* 间接寻址访存次数 = 间址级数 + 1；间接寻址的地址字段指向的是「地址的地址」。
* **相对寻址的基准是取指后的 PC**（即当前指令地址 + 指令字长），这一点是计算题的高频陷阱。
* 基址寻址的基址寄存器内容由操作系统设定、程序运行期间不变；变址寻址的变址寄存器内容由用户程序修改。
* 基址 + 变址可以组合使用：EA = (BR) + (IX) + A，用于多维数组。

### 3.3 例题：有效地址计算

**例 3** 某机按字节编址，指令字长 16 位，格式为 `OP(4) | 寻址特征(4) | A(8)`，指令存放在 2000H、2001H 两个字节中。
已知 A = 10H（8 位补码，正数），(0010H) = 3000H，R1 = 0020H，(0020H) = 4000H，
BR = 5000H，IX = 0030H，SP = 6000H。求各种寻址方式下的有效地址或操作数。

```text
取指后 PC = 2002H（指令占 2 字节）

① 立即寻址：操作数 = 10H，无有效地址
② 直接寻址：EA = A = 0010H
③ 间接寻址：EA = (0010H) = 3000H
④ 寄存器寻址：操作数 = (R1) = 0020H，无有效地址
⑤ 寄存器间接寻址：EA = (R1) = 0020H，操作数 = (0020H) = 4000H
⑥ 相对寻址：EA = (PC) + A = 2002H + 0010H = 2012H
⑦ 基址寻址：EA = (BR) + A = 5000H + 0010H = 5010H
⑧ 变址寻址：EA = (IX) + A = 0030H + 0010H = 0040H
⑨ 堆栈寻址：EA = (SP) - 2 = 5FFEH（以先减后存的递减栈、字长 2 字节为例）
```

若位移量为负数（如 A = F6H = -10），则相对寻址 EA = 2002H - 000AH = 1FF8H，实现**向后转移**，循环程序正是靠它跳回循环体开头。

**例 4** 用变址寻址实现数组遍历：数组首址 A = 1000H，元素为 2 字节，第 i 个元素地址为 1000H + 2i。
令 IX 初值为 0，每循环一次 IX 加 2，则 `LOAD R1, (IX)+A` 依次访问 1000H、1002H、1004H…，无需修改指令本身，这就是变址寻址适合数组处理的原因。

### 3.4 三种「加」的寻址方式对比

| 对比项 | 相对寻址 | 基址寻址 | 变址寻址 |
| --- | --- | --- | --- |
| 基准 | PC（取指后） | 基址寄存器 BR | 变址寄存器 IX |
| 谁在变 | 指令地址（程序位置） | 程序运行期间不变 | 每次循环由用户修改 |
| 主要用途 | 转移、程序浮动 | 多道程序重定位、扩大寻址范围 | 数组、字符串、循环 |
| 面向对象 | 程序 | 系统（操作系统） | 用户（程序员） |

## 4 指令类型

| 类型 | 典型指令 | 说明 |
| --- | --- | --- |
| 数据传送 | MOV、LOAD、STORE、PUSH、POP | 不改变数据内容，只搬运；LOAD/STORE 访存 |
| 算术逻辑 | ADD、SUB、MUL、AND、OR、XOR、CMP | 由 ALU 完成，影响标志位 |
| 移位 | SHL、SHR、SAR、ROL、ROR | 分逻辑移位、算术移位、循环移位 |
| 转移（控制流） | JMP、JZ、JNZ、CALL、RET | 改变 PC，可能引起流水线控制冒险 |
| 输入输出 | IN、OUT | 与 I/O 端口交换数据 |
| 系统 | 停机、开中断、关中断、陷阱、访管 | 由特权指令或异常机制实现 |

## 5 CISC 与 RISC

### 5.1 对比

| 对比项 | CISC（复杂指令系统） | RISC（精简指令系统） |
| --- | --- | --- |
| 指令数量 | 多（几百条） | 少（几十到一百多条） |
| 指令长度 | 变长，格式多 | 定长，格式少而规整 |
| 寻址方式 | 多（十几种） | 少（通常 3~5 种） |
| 访存指令 | 任何指令都可访存 | 只有 LOAD / STORE 访存（load-store 结构） |
| 寄存器数量 | 少 | 多（减少访存次数） |
| 控制器实现 | 多用微程序控制 | 多用硬布线（组合逻辑）控制 |
| 流水线 | 难以流水（指令长度不一） | 易于流水，可超标量、超流水 |
| 程序代码 | 短（一条指令做更多事） | 长（指令简单，条数多） |
| 编译优化 | 依赖硬件复杂度 | 便于编译器调度与优化 |
| 典型代表 | x86、VAX | ARM、MIPS、RISC-V、Power |

### 5.2 理解要点

* RISC 的核心是「**简单规则带来高效流水**」：定长指令、load-store 结构、大量寄存器，使取指、译码、执行各段时长均衡。
* CISC 的核心是「**用硬件复杂度换取代码密度**」，适合存储紧张的年代；现代 x86 内部也把复杂指令翻译成类 RISC 的微操作再流水执行，二者界限在模糊。
* 「RISC 一定比 CISC 快」是错的：性能取决于实现工艺、流水线效率与编译器质量。

## 6 指令流水线基本概念

### 6.1 基本思想

把一条指令的执行过程划分为若干**流水段**，每段由独立部件完成，各段同时工作、指令像流水一样依次通过。典型五段：

```text
IF（取指） → ID（译码 / 取数） → EX（执行） → MEM（访存） → WB（写回）
```

* 流水线充满后，每个时钟周期完成一条指令，理想情况下吞吐率提高 k 倍（k 为段数）。
* 代价：增加寄存器（锁存器）开销、各段时间需均衡（以最慢段为准）、存在相关冒险。

### 6.2 流水线分类

| 分类角度 | 类型 | 说明 |
| --- | --- | --- |
| 按级别 | 部件级、处理机级、处理机间 | 运算器流水、指令流水、宏流水（多机流水） |
| 按功能 | 单功能、多功能 | 多功能流水线可在不同时间实现不同功能 |
| 按连接 | 线性、非线性 | 线性流水线各段串联无反馈；非线性有反馈（如浮点加减） |
| 按流动 | 静态、动态 | 静态流水线同一时刻只按一种功能流动；动态可混合 |

### 6.3 性能公式（详见中央处理器一章）

设流水线有 k 段，每段用时 Δt，连续执行 n 条指令：

```text
总时间   T = (k + n - 1) × Δt
吞吐率   TP = n / T = n / ((k + n - 1) × Δt)
加速比   S  = n × k × Δt / T = n × k / (k + n - 1)
效率     E  = S / k = n / (k + n - 1)
```

当 n → ∞ 时，TP → 1/Δt，S → k，E → 1，这是流水线的理论上限。

### 6.4 影响流水线的因素

* **结构相关（资源冲突）**：多条指令争用同一部件（如同时访存），靠停顿或增设部件（指令 Cache 与数据 Cache 分离）解决。
* **数据相关**：后一条指令用到前一条指令尚未写回的结果，主要形式是 RAW（写后读），靠数据转发（旁路）、编译调度、停顿解决。
* **控制相关**：转移指令改变 PC，已取入的指令作废，靠分支预测、延迟转移、预取目标指令解决。

## 7 常考题型小结

* 指令格式：给定位段划分，计算操作码最多条数、地址码可表示的寻址范围（如 A 为 8 位、按字节编址则直接寻址范围为 256B）。
* 扩展操作码：牢记「剩余编码 × 2^借位数」，从三地址逐级向下推；反向题用「向上取整占用扩展标志」。
* 寻址方式：能写出每种方式的 EA 表达式、判断访存次数；相对寻址一定用**取指后的 PC** 作基准。
* 寻址方式选择：立即 / 寄存器最快；间接扩大范围但慢；基址面向系统重定位；变址面向用户处理数组。
* CISC / RISC：从指令数量、长度、寻址方式、访存限制、控制器实现、流水线友好度六个维度对比。
* 流水线：会画时空图、会算 T、TP、S、E；能区分结构 / 数据 / 控制相关并给出解决办法。
* 常见陷阱：间接寻址访存次数、相对寻址基准 PC、指令字长与机器字长不是一回事、变长指令对流水线不友好。
