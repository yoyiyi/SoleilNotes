## 1 面试流程

校招与社招的流程大体一致，只是轮次和侧重点不同：简历筛选 → 笔试 → 技术面（1~3 轮）→ HR 面 → 发 offer。校招通常两轮技术面加一轮 HR 面；社招可能增加交叉面、总监面或主管面。

| 环节 | 时长 | 考察重点 | 准备方式 |
| --- | --- | --- | --- |
| 简历 | — | 项目真实性、技术栈匹配度 | 用 STAR 写项目，量化结果 |
| 笔试 | 60~120 分钟 | 算法、基础选择/填空 | 刷高频题，练手速与边界 |
| 技术一面 | 45~60 分钟 | 基础 + 项目 + 1~2 道算法 | 八股成体系，算法能写能讲 |
| 技术二面 | 60 分钟 | 项目深挖、场景设计、算法 | 准备 2 个能讲深的项目 |
| 交叉/主管面 | 30~45 分钟 | 潜力、稳定性、沟通表达 | 准备职业规划与反问 |
| HR 面 | 20~30 分钟 | 动机、稳定性、薪资期望 | 想清楚底线与优先级 |

## 2 各轮考察重点

* 简历关看「匹配」：技术栈、项目复杂度、结果是否可量化，写不清楚的项目会被追问到崩。
* 笔试看「基本功 + 手速」：先做有把握的题，边界用例（空输入、单元素、溢出）一定要自测。
* 一面看「基础是否扎实」：语言特性、框架原理、计算机网络，通常从项目里挑一个点往下问。
* 二面看「深度与设计能力」：同一个问题连环追问「为什么这样设计」「换个场景怎么办」。
* 主管/交叉面看「是否值得长期合作」：表达是否有条理、遇到难题怎么拆解、对业务的理解。
* HR 面看「稳定性与动机」：为什么选这个岗位、能接受什么样的工作节奏、期望薪资是否在预算内。

## 3 自我介绍模板

控制在 60~90 秒，结构固定为「我是谁 → 我会什么 → 我做成过什么 → 为什么匹配这个岗位」。下面的示例是通用模板，按自己的经历替换内容即可。

```text
面试官您好，我是 XX，XX 大学计算机专业 XX 届本科/硕士。

我主要做 Android（或后端）开发，主力语言是 Java/Kotlin，熟悉
XX 框架和 XX 中间件，也了解 XX 方向的基本原理。

最近一年我在 XX 项目里负责 XX 模块，通过 XX 方案把 XX 指标
从 A 优化到 B，过程中比较系统地处理了 XX 类问题。

我看到岗位描述里提到 XX，这部分我在项目中有过实践，所以
觉得比较匹配，希望能有机会深入交流。
```

* 三段式：基本信息（10 秒）→ 技术栈与代表项目（40 秒）→ 匹配点与收尾（10 秒）。
* 只讲与岗位相关的内容，学生工作、与岗位无关的奖项一句带过。
* 埋钩子：主动提到一个自己最熟的技术点，引导面试官往那里问。
* 不要背简历流水账，也不要一上来就讲三分钟项目细节。

## 4 项目介绍 STAR 法则

| 要素 | 含义 | 常见错误 |
| --- | --- | --- |
| Situation | 项目背景、规模、你的角色 | 只讲公司业务，不讲自己 |
| Task | 你负责的目标与约束（时间、人力、指标） | 把团队目标说成个人目标 |
| Action | 技术选型、方案对比、你具体做了什么 | 只讲「用了什么」，不讲「为什么」 |
| Result | 量化结果、上线效果、沉淀 | 没有数字，或数字无法解释 |

示例（虚构，按自己的项目替换）：商品列表页优化。

* S：电商 App 的商品列表页在低端机上滑动掉帧，用户反馈卡顿，页面 PV 较高。
* T：我负责把列表滑动帧率从 40fps 提升到 55fps 以上，两周内上线，不能改动接口协议。
* A：先用 Perfetto 抓取一帧的耗时，定位到 measure/layout 超时和图片在主线程解码；对比「减少布局层级」「修复 ViewHolder 复用」「图片采样 + 预解码」「DiffUtil 局部刷新」几个方案的成本与收益，最终组合使用后三项，并补了帧率埋点。
* R：帧率提升到 58fps，卡顿反馈下降约 70%，方案整理成团队规范，后续新页面直接复用。

* 讲项目时把 60% 的时间留给 Action：为什么选这个方案、放弃了什么、遇到什么坑。
* 每个技术点都准备一层「再往下问」的答案，例如「为什么采样能降耗时」。
* 结果尽量给对比数据，没有线上数据就给压测数据或本地复现数据。

## 5 常见追问与应对

| 追问 | 考察点 | 应对思路 |
| --- | --- | --- |
| 这个方案为什么不用 X？ | 技术广度与权衡 | 先讲约束条件，再按复杂度、维护成本、团队熟悉度对比，承认 X 在别的场景更合适 |
| 你具体做了什么？ | 经历真实性 | 用「我做了 A，因为 B，结果是 C」回答，不夸大、不把团队成果说成个人成果 |
| 如果流量涨 10 倍会怎样？ | 扩展性思维 | 先定位瓶颈（CPU/内存/IO/连接数），再给缓存、异步、水平扩展的分层方案 |
| 项目最大的难点是什么？ | 深度与复盘能力 | 选一个真难点，讲清定位过程、试错路径和最终取舍 |
| 如果重做一次会怎么改？ | 反思能力 | 给出具体改进点，并说明当时为什么没这么做（成本/排期/信息不足） |
| 为什么离开上一家/为什么选我们？ | 动机与稳定性 | 讲成长诉求与岗位匹配，不抱怨前公司，不空谈情怀 |
| 你还有什么问题问我？ | 主动性 | 见下一节的反问清单，准备 2~3 个问题 |

## 6 反问环节问题清单

* 团队当前最紧急的技术挑战是什么？这个岗位会参与哪部分？
* 入职后前三个月的主要目标和考核方式是什么？
* 团队的开发流程是怎样的（需求评审、代码 review、测试、发布节奏）？
* 团队的技术栈和基础设施情况，有没有统一的项目脚手架或组件库？
* 新人培养机制和晋升周期大概是怎样的？
* 如果今天面试有没答好的地方，方便给一些反馈吗？（放在最后，姿态放低）
* 不建议问：薪资细节（留到 HR 面）、官网能查到的信息、直接问「加班多不多」（可以换成「团队一般的发布节奏和值班安排」）。

## 7 高频考点清单

### 7.1 Java

* HashMap 的底层结构、扩容机制、为什么容量是 2 的幂、树化与退化阈值。
* ConcurrentHashMap 在 JDK 1.8 的实现（CAS + synchronized + 扩容协助）。
* volatile 的内存语义与 happens-before 规则。
* synchronized 的锁升级过程（偏向锁、轻量级锁、重量级锁）。
* 线程池的七个参数、任务提交与执行流程、四种拒绝策略。
* JVM 运行时数据区、对象创建过程、逃逸分析与栈上分配。
* 垃圾回收算法、分代收集、G1 与 CMS 的区别。
* 类加载过程与双亲委派模型，如何打破双亲委派。
* String 的不可变性、字符串常量池、`intern()` 的行为。
* `==` 与 `equals` 的区别，重写 `equals` 为什么必须重写 `hashCode`。
* 泛型与类型擦除，擦除带来的限制。
* 反射、JDK 动态代理与 CGLIB 的区别。
* 异常体系：受检异常与非受检异常的使用场景。
* 集合框架：ArrayList 扩容、LinkedList 结构、TreeMap 的红黑树。
* Java 内存模型、指令重排、CAS 与 ABA 问题。

### 7.2 Android

* Activity 生命周期与四种启动模式，`onNewIntent` 的调用时机。
* Activity 启动流程：Launcher → AMS → Application → Activity。
* 事件分发机制：`dispatchTouchEvent`、`onInterceptTouchEvent`、`onTouchEvent` 的顺序。
* View 的绘制流程（measure/layout/draw）与自定义 View 的注意事项。
* Handler、Looper、MessageQueue 的原理，同步屏障与 IdleHandler。
* Binder 机制与 AIDL，为什么 Android 用 Binder 而不是共享内存。
* 进程间通信方式的对比与适用场景。
* 内存泄漏的常见场景与 LeakCanary 的检测原理。
* 性能优化：启动优化、内存优化、绘制优化、包体积优化、网络优化。
* 线程池与协程的对比，协程的挂起与恢复原理。
* Jetpack 组件：ViewModel、LiveData、Room、WorkManager 的职责边界。
* 组件化、插件化、热修复的基本原理与限制。
* APK 打包流程与 v1/v2/v3 签名的区别。
* RecyclerView 的四级缓存与局部刷新。
* ANR 的常见原因与定位方法。

### 7.3 计算机网络

* TCP 三次握手与四次挥手，为什么握手是三次、挥手是四次。
* TIME_WAIT 的作用、过多时的排查与处理。
* TCP 与 UDP 的区别及各自适用场景。
* 滑动窗口、流量控制与拥塞控制（慢开始、拥塞避免、快重传、快恢复）。
* HTTP/1.1、HTTP/2、HTTP/3 的主要改进。
* HTTPS 的握手过程，对称加密与非对称加密如何配合。
* 证书链校验过程与中间人攻击的防范。
* DNS 解析过程，递归查询与迭代查询。
* 从输入 URL 到页面展示的完整链路。
* HTTP 缓存：强缓存与协商缓存，`Cache-Control` 与 `ETag`。
* 常见状态码的含义与使用场景。
* GET 与 POST 的区别，以及「幂等性」的含义。

### 7.4 算法

* 数组、链表、栈、队列、哈希表的基本操作与复杂度。
* 二叉树的遍历、层序遍历、二叉搜索树、最近公共祖先。
* 递归与分治的思想，递归的终止条件与复杂度分析。
* 排序：快排、归并、堆排的实现、复杂度与稳定性。
* 二分查找及左右边界的写法。
* 滑动窗口与双指针的适用条件。
* 回溯：排列、组合、子集与去重剪枝。
* 动态规划：背包、最长递增子序列、编辑距离。
* BFS/DFS 与图的最短路径。
* 单调栈与单调队列。
* 并查集与路径压缩。
* TopK 问题的堆解法与快速选择。

## 8 面试后的复盘方法与记录模板

* 24 小时内复盘：记忆还新鲜，趁热记录题目、思路、卡点和面试官的追问方向。
* 把问题分类：知识盲区、会但没讲清、算法手速不够、项目深挖准备不足，四类问题的补法完全不同。
* 三步复盘：还原（写出当时的思路）→ 归因（是不会，还是没表达好）→ 行动（补一篇笔记、刷 3 道同类题、重写项目讲稿）。
* 面试记录建议用固定字段，方便横向对比多次面试的共性问题。

```text
日期 / 公司 / 岗位：
轮次 / 面试官角色：
流程与时长：
题目与考点：
我的回答（要点）：
卡住的地方：
面试官的反馈或追问方向：
归因（知识 / 表达 / 手速 / 项目）：
改进动作与完成时间：
```

* 连续面挂同一类问题时，优先补这个方向，而不是继续海投。
* 每轮面试都更新一次「项目讲稿」，把被追问最多的问题补进讲稿。
* 心态上把面试当作「免费的技术评审」：反馈比结果更有价值，但不要把单次结果等同于能力。
