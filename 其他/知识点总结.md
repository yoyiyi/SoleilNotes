## 2 Java 知识点

### 2.1 Java 基础

* Java 语言有什么特点？
  答：面向对象、平台无关（靠 JVM 跑字节码）、自动内存管理（GC）、强类型静态语言；支持多线程、反射，生态庞大。
* 面向对象三大特征
  答：封装隐藏实现细节；继承复用父类能力；多态靠重写 + 向上转型，同一调用有不同的运行时表现。
* Java 和 C++ 的区别?
  答：Java 无指针、单继承 + 接口、自动 GC、跨平台靠 JVM；C++ 有多继承、手动内存管理、直接编译成本地码。
* import java 和 javax 有什么区别？
  答：只是包名不同，功能没区别；java 是核心包，javax 早期是扩展包，后来一部分（如 javax.annotation）已并入 Java SE。
* JVM、JDK、JRE 区别？
  答：JDK 含 JRE + 编译打包工具；JRE 含 JVM + 核心类库；JVM 负责执行字节码，包含关系 JDK ⊃ JRE ⊃ JVM。
* Java 语言是编译与解释并存？
  答：是。javac 先编译成字节码，JVM 解释执行，热点代码由 JIT 编译成本地码，所以说编译与解释并存。
* Java 注释
  答：单行 //、多行 /* */、文档注释 /** */（可被 javadoc 提取成文档）；注释不参与编译。
* Java 标识符和关键字
  答：标识符由字母、数字、_、$ 组成，不能数字开头、不能是关键字；关键字全小写，goto、const 是保留字未使用。
* Oracle JDK 和 OpenJDK 的区别？
  答：同源；OpenJDK 开源免费，Oracle JDK 曾含商用特性 + 付费支持。JDK 11 之后两者代码基本一致，按许可选。
* 访问修饰符 public、private、protected、以及不写（默认）时的区别？
  答：private 本类；默认（包）同包；protected 同包 + 子类；public 全局。可见范围依次变大。
* String 是最基本的数据类型吗？
  答：不是。String 是引用类型（final 类），基本类型只有 8 种：byte、short、int、long、float、double、char、boolean。
* String s = new String("xyz");创建了几个字符串对象？
  答：常量池已有 "xyz" 时 1 个（堆对象）；没有时 2 个（常量池一个 + new 出来的堆对象），s 指向堆对象。
* 是否可以继承 String 类？
  答：不行。String 是 final 类且构造器私有；要扩展就用组合、装饰，或自己实现 CharSequence。
* float f=3.4;是否正确？
  答：错。3.4 字面量默认是 double，必须写 3.4f 或 (float) 3.4 强转，否则编译期就报精度丢失。
* short s1 = 1; s1 = s1 + 1;有错吗?short s1 = 1; s1 += 1;有错吗？
  答：第一句错，s1 + 1 结果提升为 int，需强转；第二句对，+= 自带隐式类型转换。
* int 和 Integer 区别？
  答：int 是基本类型，存值、默认 0；Integer 是包装类，可为 null、默认 null，能用于泛型和集合。
* new Integer(120) 与 Integer.valueOf(120) 有何区别？
  答：new 每次都在堆上新建对象；valueOf 走缓存（-128~127）复用同一对象，所以 == 比较结果可能不同。
* &和&&的区别？
  答：& 是按位与/非短路逻辑与，两边都会执行；&& 是短路与，左边为 false 时右边不执行。
* Math.round(11.5) 等于多少？Math.round(-11.5)等于多少？
  答：12 和 -11。规则是 floor(x + 0.5)，即向正无穷方向四舍五入。
* switch 是否能作用在 byte 上，是否能作用在 long 上，是否能作用在String上？
  答：byte/short/char/int 及包装类、enum、String（Java 7 起）都可以；long 不行。
* 用最有效率的方法计算2乘以8
  答：2 << 3，左移 3 位等于乘 8；位运算最快，JVM 也会自动做这类优化。
* 数组有没有 length() 方法？String 有没有 length() 方法？
  答：数组只有 length 属性，没有 length()；String 用 length()，集合用 size()。
* 在 Java 中，如何跳出当前的多重嵌套循环？
  答：用带标签的 break（outer: … break outer;），或把循环抽成方法直接 return，或加标志位。
* 构造器（constructor）是否可被重写（override）？
  答：不能。构造器不能被继承，只能重载；子类用 super() 调用父类构造器。
* 两个对象值相同 x.equals(y) == true，但却可有不同的 hashcode，对不对？
  答：不对。equals 相等则 hashCode 必须相等，否则放进 HashMap/HashSet 会查不到、去重失效。
* 当一个对象被当作参数传递到一个方法后，此方法可改变这个对象的属性，并可返回变化后的结果，那么这里到底是值传递还是引用传递？（Java 没有引用传递，只有值传递）
  答：值传递。传对象时传的是引用的副本，所以能改对象内容，但无法让外部引用指向新对象。
* String 和 StringBuilder、StringBuffer的区别？
  答：String 不可变；StringBuilder 可变、非线程安全、最快；StringBuffer 可变、方法加 synchronized、线程安全。
* 重载（Overload）和重写（Override）的区别，重载的方法能否根据返回类型进行区分？
  答：重载同名额不同参、编译期绑定；重写子类覆盖父类同签名方法、运行期多态。不能只靠返回类型区分重载。
* 抽象类（abstract class）和接口（interface）有什么异同？
  答：都不能实例化；抽象类单继承、可有构造器和状态；接口多实现、成员默认 public。Java 8 起接口可有 default/static 方法。
* char 型变量中能不能存贮一个中文汉字，为什么？
  答：能。char 是 16 位 Unicode，常用汉字都在 BMP 内占一个 char；生僻字（增补平面）要用两个 char 或 int。
* 静态嵌套类(Static Nested Class)和内部类（Inner Class）的不同？
  答：静态嵌套类不持有外部类引用，可直接 new；内部类隐式持有外部实例，需外部对象创建，能访问外部成员。
* 抽象的（abstract）方法是否可同时是静态的（static）,是否可同时是本地方法（native），是否可同时被 synchronized 修饰？
  答：都不行。abstract 无方法体、要求被重写；static 不能多态，native 有本地实现，synchronized 锁的是方法体。
* 一个类中静态（static）方法是否可以调用非静态（non-static）方法？
  答：不可以。静态方法随类加载就可用，此时可能还没有对象，非静态成员依赖 this，编译期报错。
* 如何实现对象克隆？
  答：实现 Cloneable 并重写 clone()（浅拷贝）；要深拷贝就手动克隆引用字段，或用序列化/反序列化。
* 断点续传?
  答：记录已下载字节数，请求头带 Range: bytes=n-，服务端回 206；客户端用 RandomAccessFile 定位续写。
* Java 中的 final 关键字有哪些用法？
  答：修饰类不可继承、修饰方法不可重写、修饰变量为常量（引用不可变、内容可变）、修饰参数不可改。
* try{}里有一个return语句，那么紧跟在这个try后的finally{}里的代码会不会被执行，什么时候被执行，在return前还是后?
  答：会执行，在 return 表达式求值之后、方法真正返回之前；若 finally 也有 return 会覆盖 try 的返回值。
* 阐述 final、finally、finalize 的区别？
  答：final 是修饰符表不可变；finally 是异常处理里必然执行的代码块；finalize 是 Object 回收前回调，已废弃。
* Collection和Collections的区别？
  答：Collection 是集合顶层接口（List/Set 的父接口）；Collections 是工具类，提供 sort、unmodifiableList 等静态方法。
* 字符型常量和字符串常量的区别？
  答：'a' 是 char，单引号、占 2 字节、可参与运算；"a" 是 String 对象，双引号、进常量池、有 length()。
* Java 基本类型占用内存大小？
  答：byte 1、short 2、int 4、long 8、float 4、double 8、char 2、boolean 1（JVM 内常按 int 处理）。
* continue、break、和 return 的区别？
  答：continue 跳过本次循环进入下一次；break 跳出当前循环或 switch；return 结束方法并返回值。
* == 和 equals 区别？
  答：== 比较基本类型的值或引用地址；equals 默认比地址，被重写后比内容（如 String、包装类）。
* hashCode() 与 equals()
  答：equals 判内容是否相等，hashCode 决定落在哪个哈希桶；两者必须一致重写，先比 hash 再比 equals 提升查找效率。
* 在 Java 中定义一个不做事且没有参数的构造方法的作用？
  答：显式保留无参构造。一旦写了带参构造，编译器就不再生成默认无参构造，子类 super() 会编译失败。
* 对象的相等与指向他们的引用相等，两者有什么不同?
  答：引用相等指同一个地址（== 为 true）；对象相等指内容相同（equals 为 true），两个不同对象可以内容相等。
* 在一个静态方法内调用一个非静态成员为什么是非法的？
  答：静态方法不需要对象就能调用，此时可能没有实例，非静态成员必须由 this 访问，编译器直接拒绝。
* Object 类常见的方法？
  答：equals、hashCode、toString、getClass、clone、finalize，以及 wait/notify/notifyAll 线程通信方法。
* Java 序列化中如果有些字段不想进行序列化，如何做？
  答：用 transient 修饰该字段（static 字段本来就不序列化）；也可自定义 writeObject/readObject 控制。
* 重载和重写的区别？
  答：重载在同一定义域内同名不同参、编译期决定；重写在父子类间签名相同、运行期动态绑定。
* 成员变量与局部变量区别？
  答：成员变量有默认值、随对象在堆上、可被修饰符修饰；局部变量必须显式初始化、在栈帧中、不能加 static。
* 类的构造方法的作用是什么? 若一个类没有声明构造方法，该程序能正确执行吗? 为什么?
  答：作用是初始化对象；能正常执行，编译器会自动补一个无参默认构造（父类没有无参构造时才会报错）。
* 为什么不能通过返回值类型区分重载？
  答：调用时可以忽略返回值（如 a.foo();），编译器无法只凭返回值类型判断该调哪个方法。
* BIO、NIO、AIO 区别？
  答：BIO 同步阻塞、一连接一线程；NIO 同步非阻塞、Selector 多路复用；AIO 异步回调，由系统通知完成。
* 装箱和拆箱的原理？
  答：装箱调 Integer.valueOf()，拆箱调 intValue()；-128~127 走 IntegerCache 复用对象，超出范围新建。
* 反射
  答：运行时拿到类信息并操作对象：Class → Constructor/Method/Field，可突破 private，但性能低、破坏封装。
* Java 泛型
  答：参数化类型，编译期做类型检查、省去强转；只在编译期生效，不能 new T()、不能用基本类型做参数。
* 泛型类型擦除？
  答：编译后泛型参数被替换成上界（默认 Object），必要时生成桥接方法；运行期拿不到真实类型参数。
* 获取 Class 对象的方法？
  答：类名.class、对象.getClass()、Class.forName("全类名")、类加载器 loadClass()；基本类型用 int.class。
* 反射中创建对象的两种方法？
  答：Class.newInstance()（已废弃，只能调 public 无参构造）和 getConstructor(参数).newInstance(实参)（推荐）。
* 为什么重写 equals 时必须重写 hashCode 方法？
  答：契约要求 equals 相等则 hashCode 相等，否则放进 HashMap/HashSet 会出现查不到、去重失效。
* 解决Hash碰撞冲突方法？
  答：链地址法（HashMap 拉链 + 红黑树）、开放地址法（线性/二次探测）、再哈希法、公共溢出区。
* 深拷贝和浅拷贝？
  答：浅拷贝只复制引用，两个对象共享内部对象；深拷贝递归复制内部对象，彼此完全独立。
* 说说 Java 异常体系？
  答：Throwable 分 Error（不可恢复，如 OOM）和 Exception；Exception 又分受检（IOException）和非受检（RuntimeException）。
* Java I/O 分为几种？
  答：按方向分输入/输出，按单位分字节流（InputStream/OutputStream）和字符流（Reader/Writer），另有 NIO、AIO。
* 那些状态下 finally 不会被执行？
  答：System.exit 退出 JVM、线程被强制杀死、守护线程随进程结束、执行 finally 前断电或死循环。

### 2.2 Java 容器

* ArrayList、LinkedList、Vector 区别？
  答：ArrayList 数组、随机访问快、扩容 1.5 倍；LinkedList 双向链表、头尾增删快；Vector 数组但方法同步、扩容 2 倍，已少用。
* list、set、map 区别？
  答：List 有序可重复、按索引访问；Set 不重复、无序；Map 存键值对、key 不重复。
* HashSet、LinkedHashSet、TreeSet 区别、源码？
  答：HashSet 内部是 HashMap、无序；LinkedHashSet 用 LinkedHashMap 记住插入顺序；TreeSet 用 TreeMap 红黑树，按比较器排序。
* HashMap、LinkedHashMap、Hashtable、TreeMap 区别、源码？
  答：HashMap 数组 + 链表 + 红黑树、无序、线程不安全；LinkedHashMap 多一条双向链表保序；Hashtable 全表加锁已淘汰；TreeMap 红黑树、有序。
* List、Set、Map 区别？
  答：都是集合框架的接口；List、Set 继承 Collection，Map 独立；List 有序可重复，Set 不重复，Map 是键值对。
* ArrayList 和 Vector 区别？
  答：都基于数组；Vector 方法加 synchronized、扩容 2 倍、线程安全但慢；ArrayList 扩容 1.5 倍、非线程安全。
* 说说 ConcurrentHashMap？
  答：JDK 8 用 CAS + synchronized 锁桶头节点，读不加锁；7 及以前是分段锁。不允许 null 键值，多线程协助扩容。
* ArrayList 扩容机制？
  答：默认容量 10（首次 add 才创建数组），满了按 old + old>>1 扩为 1.5 倍，用 Arrays.copyOf 复制到新数组。
* 说说 ArrayList 源码中 ensureCapacity() 作用吧？
  答：一次性扩容到指定容量，避免多次 add 触发多次复制；已知数据量时先调用可减少扩容开销。
* HashMap 的长度为什么是 2 的幂次方？
  答：这样 hash & (n-1) 等价于取模但更快，且低位分布均匀；扩容时元素要么留在原位，要么移到原下标 + 旧容量。
* comparable 和 Comparator 的区别?
  答：Comparable 由类自己实现 compareTo，只有一种默认排序；Comparator 是外部比较器，可写多种排序、不改源码。

### 2.3 Java 并发

* sleep() 和 wait() 区别？
  答：sleep 是 Thread 静态方法，不释放锁，到点自动醒；wait 是 Object 方法，必须在同步块内、会释放锁，要靠 notify 唤醒。
* sleep() 方法和 yield() 区别？
  答：sleep 阻塞指定时间、不释放锁；yield 只是让出 CPU 给同优先级线程，状态回到就绪，可能马上又被调度。
* 实现多线程程序有几种实现方式？
  答：继承 Thread、实现 Runnable、实现 Callable + FutureTask（有返回值）、提交到线程池；最终都由 Thread 执行 run。
* 线程的生命周期？
  答：NEW、RUNNABLE（就绪 + 运行）、BLOCKED（等锁）、WAITING、TIMED_WAITING、TERMINATED。
* 为什么线程启动要调用 start()，而不是直接调用 run()?
  答：start 会真正创建新线程并让 JVM 回调 run，实现并发；直接调 run 只是当前线程里的普通方法调用。
* interrupt()、interrupted()、isInterrupted() 区别？
  答：interrupt 设置中断标志；interrupted 是静态方法，返回并清除标志；isInterrupted 只查询、不清除。
* start()、run() 区别？
  答：start 启动新线程、只能调一次（重复抛 IllegalThreadStateException）；run 只是线程体，普通方法调用。
* 说说乐观锁、悲观锁、自旋锁、共享锁、独占锁、重量级锁、轻量级锁？
  答：乐观锁假设无冲突、用 CAS 重试；悲观锁先加锁；自旋锁忙等不阻塞；共享锁可多读（读锁），独占锁互斥（写锁）；重量级锁靠 OS 互斥量，轻量级锁靠 CAS + 对象头。
* 说说 synchronized？
  答：JVM 内置锁，可修饰方法或代码块，锁对象是 this/Class；保证原子性、可见性、有序性，异常或退出自动释放。
* 说说 ReentrantLock ？
  答：基于 AQS 的可重入独占锁，支持公平/非公平、可中断、超时 tryLock、多个 Condition，必须手动 unlock。
* 说说线程的死锁吧？
  答：两个以上线程各持一把锁又等对方的锁，永久阻塞；需同时满足互斥、持有并等待、不可抢占、循环等待。
* 如何避免死锁？
  答：固定加锁顺序、缩小锁范围、用 tryLock 带超时、一次性申请全部资源、减少锁嵌套。
* 程序计数器为什么设计成私有？
  答：它记录当前线程执行到哪条字节码，线程切换后要能恢复现场；每个线程有独立执行流，所以必须私有。
* 虚拟机栈和本地方法栈为什么设计成私有？
  答：栈帧里是局部变量表、操作数栈，生命周期与线程一致；只有私有才能保证各线程方法调用互不干扰。
* 公平锁、非公平锁、可重入锁？
  答：公平锁按 FIFO 排队；非公平锁允许插队、吞吐更高（ReentrantLock 默认非公平）；可重入锁同一线程可重复获取、计数加一。
* Semaphore 信号量
  答：用 permits 计数控制并发数，acquire 减一、release 加一；常用于限流、连接池，可设公平模式。
* JDK 1.6 synchronized 作了那些优化？
  答：引入偏向锁、轻量级锁、自适应自旋、锁消除、锁粗化，无竞争时避免陷入内核态；偏向锁 15 起默认关闭。
* 说说 ThreadPoolExecutor 构造方法的参数？
  答：core 与 max 线程数、keepAlive、unit、workQueue、threadFactory、handler；先扩 core、再入队、满了扩 max、还满则拒绝。
* 说说 Java 阻塞队列？
  答：ArrayBlockingQueue 有界数组、LinkedBlockingQueue 链表、SynchronousQueue 不存、PriorityBlockingQueue 优先级、DelayQueue 延时。
* CyclicBarrier、CountDownLatch、Semaphore 的用法？
  答：CountDownLatch 一次性等 N 个任务做完（countDown/await）；CyclicBarrier 可循环，让一批线程互等到齐；Semaphore 控制并发数。
* 说说 volatile？
  答：保证可见性和有序性（禁重排），不保证原子性；写立即刷主存、读强制从主存取，适合状态标志、一次性发布。
* 上下文切换？
  答：CPU 从一个线程切到另一个时要保存/恢复寄存器和 PC；线程过多、锁竞争激烈会导致切换频繁、性能下降。
* 说说 ThreadLocal ？
  答：每个线程有自己的副本，底层 ThreadLocalMap 以 ThreadLocal 为弱引用 key；线程池里用完必须 remove，否则泄漏。
* 进程调度算法？
  答：先来先服务 FCFS、短作业优先 SJF、时间片轮转 RR、优先级调度、多级反馈队列；目标是吞吐高、响应快、公平。
* 线程有哪些基本状态？
  答：Java 里 6 种：NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING、TERMINATED；操作系统层面是就绪、运行、阻塞。
* 并发和并行区别？
  答：并发是多个任务在重叠的时间段内交替推进（单核也能并"发"）；并行是同一时刻真正同时执行，需要多核。
* 线程和进程区别？
  答：进程是资源分配单位、有独立地址空间；线程是 CPU 调度单位、共享进程内存，创建和切换更轻量。
* 了解 CAS 吗？
  答：Compare And Swap，内存值等于期望值才更新，靠 CPU 原子指令；无锁自旋，开销小，但有 ABA 和自旋耗 CPU 的问题。
* 说说 ABA 问题？
  答：值从 A 改成 B 又改回 A，CAS 认为没变过；用 AtomicStampedReference 加版本号，或 AtomicMarkableReference。
* AQS 了解吗？
  答：AbstractQueuedSynchronizer：volatile state + CLH 队列，acquire/release 模板方法；ReentrantLock、Semaphore 都基于它。

### 2.4 JVM

* 说说 JVM 运行时数据区？
  答：线程私有：程序计数器、虚拟机栈、本地方法栈；线程共享：堆、方法区（JDK 8 起是元空间）；另算直接内存。
* 说说 JVM 内存区域？
  答：堆存对象实例，方法区存类元信息和运行时常量池，栈存栈帧；JDK 8 用元空间（本地内存）替换永久代。
* Java 对象如何创建的，对象创建过程？
  答：类加载检查 → 分配内存（指针碰撞/空闲列表）→ 内存清零 → 设置对象头（hash、GC 年龄、锁标志）→ 执行 <init>。
* MinorGC、MajorGC、FullGC 区别？
  答：Minor 只回收新生代，频繁且快；Major/Old 回收老年代；Full 回收整个堆和方法区，常伴随 STW，最慢。
* 可作为 GC Roots 的对象？
  答：虚拟机栈中局部变量引用的对象、静态变量、常量、JNI 引用、活跃线程、被 synchronized 持有的对象等。
* 垃圾回收算法？
  答：标记-清除（有碎片）、复制（新生代）、标记-整理（老年代）、分代收集；引用计数法有循环引用问题，JVM 不用。
* 类加载机制？
  答：加载 → 验证 → 准备 → 解析 → 初始化，之后使用、卸载；准备阶段赋零值，初始化才执行 <clinit>。
* 类加载器？
  答：Bootstrap（C++ 实现，加载 JDK 核心类）、Platform/Extension、Application（classpath）以及自定义 ClassLoader。
* 双亲委派机制？
  答：加载时先委派父加载器，父加载不到才自己加载；保证核心类不被篡改、类只加载一次；可重写 loadClass 打破（热修复、SPI）。
* 内存分配策略？
  答：优先在 Eden 分配、大对象直接进老年代、长期存活对象晋升（默认 15 岁）、动态年龄判定、空间分配担保。
* 对象的访问定位有哪几种？
  答：句柄池（稳定，对象移动只改句柄）和直接指针（HotSpot 采用，少一次寻址、更快）。
* 虚拟机如何解决内存分配并发问题？
  答：CAS + 失败重试保证指针原子更新；或每个线程预先分配 TLAB，在 TLAB 内分配不用同步。
* 可作为 GC Roots 的对象包括几种？
  答：栈中引用、静态变量、常量引用、JNI 引用、活跃线程、锁对象等；本质是从这些根出发不可达即可回收。
* String s1 = new String("abc");这句话创建了几个字符串对象？
  答：常量池没有 "abc" 时 2 个（常量池对象 + 堆对象）；已有则 1 个堆对象，s1 指向堆里的那个。
* String.intern() 作用？
  答：返回常量池中该字符串的引用，池里没有就放进去（JDK 7 起常量池在堆中）；用于字符串去重、省内存。

### 2.5 设计模式

* 创建者模式
  - 单例模式
    答：私有构造 + 静态实例；推荐静态内部类或双重检查 + volatile，保证线程安全且懒加载。
  - 工厂模式
    答：把对象创建从使用方剥离；简单工厂、工厂方法（一个产品一个工厂）、抽象工厂（一族产品）。
  - 原型模式
    答：以已有对象为原型 clone 出新对象，省去重复初始化；注意浅拷贝/深拷贝。
  - 建造者模式
    答：分步构造复杂对象，链式调用、可选参数清晰；OkHttpClient.Builder、AlertDialog 都是。
* 结构型模式
  - 适配器模式
    答：转换接口让不兼容的类能协作；ListView 的 BaseAdapter、RecyclerView.Adapter 都是适配器。
  - 代理模式
    答：代理控制对真实对象的访问，可做增强；静态代理要手写，动态代理用 Proxy/InvocationHandler，Retrofit 靠它。
  - 装饰者模式
    答：包装同类型对象、动态叠加功能，比继承灵活；Java IO 的 BufferedInputStream 就是。
  - 桥接模式
    答：把抽象和实现分离成两个维度，各自独立扩展，避免类爆炸。
  - 外观模式
    答：用一个高层接口封装一组子系统调用，简化使用；如 Context 封装 AMS 等系统服务。
  - 享元模式
    答：共享可复用对象、把可变状态外置，省内存；String 常量池、线程池、RecyclerView 的 ViewHolder 池。
  - 组合模式
    答：树形结构里把叶子节点和容器节点统一对待，递归调用；View 树、文件系统。
  - 桥接模式
    答：同前——抽象与实现各一条继承线，用组合桥接，替换实现不影响抽象。
* 行为型模式
  - 模板模式
    答：父类定义流程骨架，子类实现具体步骤；AsyncTask、Activity 生命周期回调都是。
  - 策略模式
    答：把可互换的算法封装成类，运行时切换；如加载图片的缓存策略、动画插值器。
  - 命令模式
    答：把请求封装成对象，可排队、撤销、记录日志；Handler 的 Message 就是命令。
  - 职责链模式
    答：请求沿链传递，任一节点可处理或下传；View 事件分发、OkHttp 的拦截器链。
  - 状态模式
    答：对象内部状态改变时行为随之改变；用状态类替代大量 if/else，如播放器的暂停/播放。
  - 观察者模式
    答：被观察者维护观察者列表，状态变化时通知；LiveData、EventBus、RecyclerView.Adapter 的 notify。
  - 中介者模式
    答：用中介对象集中处理多方交互，减少网状依赖；如 MVP 里的 Presenter、EventBus。
  - 迭代器模式
    答：提供统一方式遍历集合而不暴露内部结构；Iterator、for-each 语法糖。
  - 访问者模式
    答：在不改元素类的前提下增加新操作，双重分派；适合结构稳定、操作多变的场景。
  - 备忘录模式
    答：保存对象某一时刻的内部状态以便恢复；如 onSaveInstanceState、编辑器的撤销栈。
  - 解释器模式
    答：为语言定义文法并写解释器求值；如算术表达式解析，业务里很少用。

## 3 Android 知识点

> **时效说明（2025）**：下面的题目整理于 2019 年前后，题目本身仍然有效，但答案要按新系统更新。Android 10 之后的行为变更请配合 [Android 版本适配](../Android/Android版本适配.md)，Compose、协程、Hilt、MVVM/MVI 等新内容见 [Jetpack Compose](../Android/Jetpack%20Compose.md)、[Kotlin 协程与 Flow](../Android/协程.md)、[Hilt 依赖注入](../Android/Hilt依赖注入.md)、[应用架构 MVVM 与 MVI](../Android/应用架构MVVM与MVI.md)；带答案的现代题库见 [Android 面试题精选（2025）](../Android/Android面试题精选（2025）.md)。

* Activity 生命周期
  答：onCreate→onStart→onResume→onPause→onStop→onDestroy；onStart 是可见，onResume 是可交互，onPause 后仍可见。
* 横竖屏切换时候 Activity 的生命周期
  答：默认销毁重建：onPause→onStop→onDestroy→onCreate→onStart→onResume；配 configChanges 则只回调 onConfigurationChanged。
* ActivityA 跳转 ActivityB 然后 B 按 back 返回 A，各自的生命周期顺序，A 与 B 均不透明？如果B是透明主题的又或是个DialogActivity 呢？
  答：A.onPause→B 创建启动→A.onStop；返回 B.onPause→A.onRestart→A.onResume→B.onDestroy。B 透明或 Dialog 时 A 不 onStop。
* Android中进程的优先级？
  答：前台 > 可见 > 服务 > 后台 > 空进程；内存不足时按此顺序回收，前台进程最不易被杀。
* onSaveInstanceState()方法的作用 ? 何时会被调用？
  答：保存临时 UI 状态，onStop 前调用（Android 9 起改为 onStop 之后）；重建时在 onCreate 或 onRestoreInstanceState 里恢复。
* Activity的四种启动模式、应用场景 ？
  答：standard 新建；singleTop 栈顶复用（通知跳转）；singleTask 栈内唯一并清空其上（首页）；singleInstance 独占任务栈（来电页）。
* Activity 常用的标记位 Flags？
  答：FLAG_ACTIVITY_NEW_TASK、SINGLE_TOP、CLEAR_TOP、CLEAR_TASK、NO_HISTORY、EXCLUDE_FROM_RECENTS。
* Activity 跟 window，view 之间的关系？
  答：Activity 持有 PhoneWindow，Window 里是 DecorView，setContentView 塞进 content；WindowManager 把 View 挂到 Surface。
* 如何启动其他应用的 Activity？
  答：用显式 ComponentName（包名 + 类名）或隐式 Intent 匹配 intent-filter；目标必须 exported=true，否则抛 SecurityException。
* 什么是 ANR？ 如何避免？
  答：主线程阻塞超时（输入事件 5s、广播 10s、前台服务 20s）就会 ANR；避免主线程 IO/锁等待，耗时任务丢子线程，用 StrictMode 排查。
* 说说 Android 中的动画？
  答：View 动画（补间 + 帧动画 drawable）、属性动画（ValueAnimator/ObjectAnimator）、过渡动画（Transition 与共享元素）。
* ACTION_CANCEL 事件触发？
  答：父容器在子 View 处理中途拦截（onInterceptTouchEvent 返回 true），或 View 被移除、窗口失焦时，子 View 收到 CANCEL 而不是 UP。
* 动画的原理？
  答：按时间插值算出每帧属性值，由 Choreographer 在 VSYNC 回调里逐帧刷新，人眼看到连续动画。
* 属性动画和 View 动画区别？
  答：View 动画只改绘制位置、属性值不变、点击区域不跟着动；属性动画真正修改对象属性，可作用于任意对象，3.0 起。
* Android 各版本新版本
  答：按线记：6 运行时权限、8 通知渠道/后台限制、9 非 SDK 接口、10 分区存储、11 包可见性、12 启动页、13 通知权限、14 前台服务类型、15 边到边、16 16KB 页。
* Serializable 和 Parcelable 的区别？
  答：Serializable 是 Java 序列化、反射实现、慢，适合存盘；Parcelable 手写读写、快，适合 Intent/Binder 传参。
* Android 为每个应用程序分配的内存大小是多少？
  答：不是固定值，由 dalvik.vm.heapgrowthlimit 决定（常见 128~512MB），getMemoryClass() 可查，largeHeap 可放宽。
* Activity 的 startActivity 和 context 的 startActivity区别？
  答：Activity 的会带上当前任务栈；Application/Service 这类 Context 没有任务栈，必须加 FLAG_ACTIVITY_NEW_TASK。
* 怎么在Service中创建Dialog对话框？
  答：Service 没有界面窗口，要用系统级弹窗 TYPE_APPLICATION_OVERLAY（8.0 起，需悬浮窗权限），或跳到透明 Activity 里弹 Dialog。
* 程序A能否接收到程序B的广播？
  答：能，但 B 的广播要显式或带包名（8.0 起隐式广播受限），B 的 receiver 需 exported=true，A 对应静态注册。
* 数据加载更多涉及到分页，你是怎么实现的？
  答：page/offset + limit 请求，RecyclerView 触底监听或 Paging3，维护 loading/hasMore 状态防重复请求。
* 编译期注解跟运行时注解有何不同？
  答：编译期注解靠 APT 生成代码，零反射开销（Room、Hilt）；运行时注解靠反射读取，灵活但慢（EventBus、老版 Retrofit）。
* 如何解析 xml，以及三种方式的区别？
  答：DOM 全量读入内存、可随机访问但占内存；SAX 事件流式、省内存但不能回退；Pull 是 Android 内置流式解析，写法更简单。
* 更新 UI 方式？
  答：主线程直接改；子线程用 runOnUiThread、View.post、Handler，或协程切 Dispatchers.Main。
* jar 和 aar 的区别？
  答：jar 只有 class 和清单；aar 还含 AndroidManifest、res、assets、jni、proguard，是 Android 库的标准产物。
* 程序自启动？
  答：监听 BOOT_COMPLETED（需 RECEIVE_BOOT_COMPLETED 权限），或用前台服务/JobScheduler；国内厂商还要加自启白名单。
* BroadcastReceiver，LocalBroadcastReceiver 区别？
  答：LocalBroadcastManager 只在应用内、基于 Handler、不跨进程，更安全；但已废弃，现用 Flow/StateFlow 或显式广播 + setPackage。
* SharedPreferences 的 apply 和 commit 有什么区别？
  答：commit 同步写磁盘、返回 boolean、阻塞当前线程；apply 先改内存、异步落盘、无返回值，主线程用 apply。
* 计算一个view的嵌套层级？
  答：递归 getChildCount/getChildAt 统计深度，或直接用 Layout Inspector、dumpsys activity top 看层级。
* asset 目录与 res 目录的区别？
  答：assets 不生成 R id、保留原目录结构、用 AssetManager 读；res 会被编译成二进制资源、有 R.id、支持限定符适配。
* 硬件加速
  答：4.0 起默认开启，绘制交给 RenderThread/GPU；可对单个 View 设 layerType 控制，注意过度绘制和离屏缓存耗显存。
* 显式 Intent 和隐式 Intent
  答：显式指定包名 + 类名，同应用内跳转；隐式只写 action/category/data，由系统匹配 intent-filter，可跨应用。
* 广播传输的数据是否有限制，是多少，为什么要限制？
  答：有限制，Intent 传大数据会抛 TransactionTooLargeException（Binder 缓冲约 1MB/进程共享），大文件应传 Uri 或落盘。
* 安卓签名机制？
  答：用私钥对 APK 摘要签名，安装时校验完整性；v1 JAR 签名、v2 整包签名、v3 支持密钥轮换、v4 配合增量安装。
* merge、ViewStub、include 的作用？
  答：include 复用布局；merge 作根节点省一层嵌套；ViewStub 惰性加载，inflate 后替换为真实布局，适合错误页。
* ContentProvider 使用
  答：跨进程共享数据，注册 authorities 并实现 onCreate/query/insert/update/delete/getType；客户端用 ContentResolver 按 URI 访问。
* Android 怎么加速启动 Activity？
  答：精简 onCreate、延迟初始化非必要组件、布局扁平化 + ViewStub、用 SplashScreen API 做启动图、避免主线程 IO。
* Json 解析方式的两种区别？
  答：org.json 简单但性能一般；Gson/Moshi 用反射或代码生成做对象映射；大文件用流式解析（JsonReader）省内存。
* Fragment懒加载
  答：只在首次可见时请求数据：容器用 setMaxLifecycle 控制，或 onResume 里判断 isResumed + isVisible，加标志位只加载一次。
* Bitmap 使用时候注意什么？
  答：按需 inSampleSize 采样防 OOM、用 RGB_565、inBitmap 复用、及时 recycle、不要主线程解码，注意 8.0 前像素在 native 内存。
* 多进程场景遇见过么？
  答：WebView 独立进程、推送/保活进程、大图处理；注意静态变量不共享、SharedPreferences 多进程不可靠，改用 MMKV 或 Provider。
* Bitmap 的 recycler()
  答：recycle 释放底层像素内存，之后再绘制会抛 "trying to use a recycled bitmap"；8.0 起像素在 Java 堆，交给 GC 即可。
* 一张Bitmap所占内存以及内存占用的计算
  答：宽 × 高 × 每像素字节数（ARGB_8888 4B、RGB_565 2B、ALPHA_8 1B），还要按 inTargetDensity/inDensity 缩放后的实际宽高算。
* 数据库升级增加表和删除表都不涉及数据迁移，但是修改表涉及到对原有数据进行迁移,如何实现？
  答：onUpgrade 里按版本逐级处理：建新表→INSERT SELECT 搬数据→删旧表→改名，全程放事务里保证原子性。
* Canvas.save() 跟 Canvas.restore()的区别
  答：save 把当前矩阵和裁剪状态压栈并返回 id，restore 出栈恢复；两者必须成对，否则画布状态错乱。
* 为什么bindService可以跟Activity生命周期联动？
  答：bindService 的 ServiceConnection 绑在调用者 Context 上，Context 销毁时系统自动解绑，Service 无引用即被销毁。
* 自定义 view 效率高于xml定义吗？说明理由。
  答：不一定。手写 View 省一次 inflate 和层级解析，启动略快；但 XML 可读性、复用和限定符适配更好，差距通常可忽略。
* Gradle 配置多渠道打包
  答：productFlavors 定义渠道，用 manifestPlaceholders 或 buildConfigField 注入渠道号，variant API 批量出包，或 Walle 二次写入。
* Service 的生命周期
  答：启动式：onCreate→onStartCommand→onDestroy；绑定式：onCreate→onBind→onUnbind→onDestroy；两者混用要 stop 且 unbind 才销毁。
* 加速启动Activity？
  答：轻量化 onCreate、延迟初始化、布局层级扁平化、WindowBackground 或 SplashScreen 过渡、别在主线程做 IO。
* 断点续传和下载
  答：用 Range 请求 + RandomAccessFile 定位续写，记录已下载长度并校验 Content-Length；后台用 WorkManager 或 DownloadManager。
* Fragment 在 ViewPager 里面的生命周期，滑动 ViewPager 的页面时 Fragment 的生命周期的变化。
  答：ViewPager 默认预加载相邻页，进入走 onAttach→onCreate→onCreateView→onStart→onResume；滑出只 onPause/onStop 不销毁。
* Android中跨进程通讯的几种方式?
  答：Binder（AIDL/Messenger）、ContentProvider、广播、Socket、共享文件；首选 Binder，共享内存（Ashmem）适合大数据。
* HandlerThread
  答：带 Looper 的后台线程，start 后取 getLooper 在该线程串行处理任务，用完 quitSafely 退出。
* IntentService
  答：已废弃（API 30）。内部是 HandlerThread + Handler，串行处理 Intent，处理完自动 stopSelf；现用 WorkManager / CoroutineWorker。
* 说一说支付流程？
  答：客户端下单→自家服务端向支付平台统一下单返回签名参数→拉起支付宝/微信 SDK→客户端回调只做提示，最终以服务端异步通知的订单状态为准。
* 如何导入外部数据库
  答：db 文件放 assets，首次启动检查 databases 目录，用文件流拷贝过去，再 openDatabase 打开。
* 如何保证Service不被杀死？
  答：前台服务 + 常驻通知、onStartCommand 返回 START_STICKY、JobScheduler 拉活、引导加白名单；8.0 起后台起服务受限，优先前台服务。
* 简单说说 LinearLayout、FrameLayout、RelativeLayout 性能？
  答：FrameLayout 最轻；LinearLayout 次之（weight 二次测量）；RelativeLayout 两次测量子 View；复杂布局用 ConstraintLayout 压平。
* 说说 scheme 跳转协议？
  答：自定义 URI（app://host/path?query），manifest 的 intent-filter 里声明，外部用 Intent 或 WebView 拦截跳转，可做路由分发、H5 唤端。
* 说说 Android 中集合框架？
  答：常用 ArrayMap/SparseArray/SparseIntArray（小数据量省内存，key 为 int 更快）、HashMap、ArrayDeque、CopyOnWriteArrayList。
* Service 和 Activity 在同一个线程吗？
  答：默认都在主线程，所以 Service 里也不能直接做耗时操作，除非 manifest 里 android:process 另起进程。
* Service 里面可以弹吐司么？
  答：可以，Toast 靠 WindowManager 加到系统窗口、不依赖 Activity；但 11 起后台自定义 View 的 Toast 受限，Dialog 也不能直接弹。
* 说说 Activity、Intent、Service 是什么关系？
  答：Activity 是界面、Service 是后台逻辑、Intent 是组件间通信的信使，startActivity/startService/bindService 都靠它传参。
* 简单说一下 IntentService
  答：已废弃，Service + HandlerThread 的组合，onStartCommand 把 Intent 入队串行执行，执行完自动停止；现用 WorkManager 替代。
* Context 是什么？一个应用有多少个 Context？
  答：Context 是访问应用环境和系统服务的入口；数量跟组件走：Application 1 个 + 每个 Activity 1 个 + 每个 Service 1 个。
* Context、Activity、Application 有什么区别？
  答：Activity 是 Context 子类、有界面和主题；Application 全局单例、生命周期最长；具体实现都是 ContextImpl，外面套不同包装。
* 实现竖向的 TextView？TextView 文字描边效果？
  答：竖向：设 ems=1 或每个字后加 \n，也可自定义逐字绘制；描边：用 STROKE 和 FILL 两种 Paint 各画一遍，或两层 TextView 叠加。
* 广播的两种注册方式 ？
  答：静态注册（manifest，常驻；8.0 起隐式广播大多收不到）和动态注册（registerReceiver，跟随组件生命周期，必须 unregister）。
* Activity 怎么和 Service 绑定，怎么在Activity 中启动自己对应的 Service？
  答：bindService(intent, conn, BIND_AUTO_CREATE) 拿到 IBinder，同进程直接强转成本地接口调用，跨进程用 AIDL。
* 如何将一个 Activity 设置成窗口的样式
  答：manifest 里给该 Activity 设 android:theme 为 Dialog 主题，配合 windowIsFloating、windowBackground 透明做成浮层。
* 简单说一下 Activity
  答：四大组件之一，一个可与用户交互的界面载体，生命周期由 AMS 通过 ActivityThread 调度，必须在 manifest 声明。
* Service 是否在 main thread 中执行, service 里面是否能执行耗时的操作?
  答：默认在主线程，不能直接做耗时操作否则 ANR；要耗时用 WorkManager 或自己开线程/协程。
* 说说ContentProvider、ContentResolver、ContentObserver 之间的关系？
  答：Provider 提供数据并实现 CRUD，Resolver 是客户端按 URI 访问的代理，Observer 监听 URI 变化（数据变了 notifyChange 通知）。
* ddms 和 traceView 的区别？
  答：DDMS 是旧版调试工具集（进程、堆、文件、线程）；TraceView 分析方法耗时，二者均已由 Android Studio Profiler / Perfetto 取代。
* Handler、Thread和HandlerThread的差别
  答：Thread 只负责跑；HandlerThread 是带 Looper 的线程；Handler 往指定 Looper 的队列发消息并处理，三者配合做线程切换。
* Android 适配方案
  答：屏幕用 dp + 限定符 + ConstraintLayout，或按设计稿改 density；版本按 targetSdk 逐条适配行为变更；刘海/折叠屏用 WindowInsets。
* Android 中 HashMap 的优化
  答：小数据量换 ArrayMap/SparseArray（省 Entry、省扩容），key 为 int 用 SparseIntArray，预估容量避免多次扩容。
* AsyncTask 的缺陷和问题，说说他的原理？
  答：已废弃（API 30）。原理是线程池 + 主线程 Handler 回调；缺陷：生命周期不同步易泄漏、并发策略混乱、异常难捕获，现用协程 + lifecycleScope。
* 说说 AndroidManifest.xml？
  答：应用清单：声明包名、组件及 exported/intent-filter、权限、minSdk/targetSdk、application 级属性；多渠道由 manifest merger 合并。
* Activity 和 Fragment 之间怎么通信，Fragment 和 Fragment 怎么通信？
  答：Activity→Fragment 用 setArguments/Bundle；Fragment→Activity 用接口回调；Fragment 间用共享 ViewModel 或 Fragment Result API。
* Android系统架构，你能说说每一层的作用吗？
  答：Linux 内核（进程/内存/驱动）→HAL（硬件抽象）→原生库 + ART 运行时→Java API Framework（AMS/PMS）→应用层。
* 反编译了解吗？
  答：apktool 解出 smali 和资源；dex2jar + jd-gui 看 Java 源码；用于安全分析，加固和混淆会加大难度。
* 为什么 bindService 可以跟Activity生命周期联动？
  答：绑定的 ServiceConnection 归属于调用者，Context 销毁时自动解绑，Service 无人引用就被销毁，比 startService 更"跟随"。
* oom 是否可以try catch ？
  答：能 catch OutOfMemoryError，但 OOM 后堆状态不可靠、几乎无法恢复；正确做法是提前优化内存，而不是靠捕获兜底。
* 如何绕过 9.0 限制
  答：9.0 限制明文 HTTP 和非 SDK 接口：前者改 HTTPS 或用 networkSecurityConfig 临时放行，后者用官方豁免或更稳定的公开 API。
* 你是如何做单元测试的
  答：JUnit + MockK/Mockito 测逻辑，Robolectric 跑 Android 依赖，Compose 用 createComposeRule，UI 用 Espresso，CI 里看覆盖率。
* 非UI线程可以更新UI吗?
  答：ViewRootImpl 有 checkThread 校验，非创建线程更新会抛 CalledFromWrongThreadException；早期版本某些情况不检查，但不能依赖。
* 怎么控制另外一个进程的View显示？
  答：跨进程不能直接操作 View；可用 SurfaceView + Binder 传 Surface（或 SurfaceControl），或用系统悬浮窗。
* Android 程序运行时权限与文件系统权限
  答：运行时权限是应用层危险权限，6.0 起动态申请；文件权限是 Linux 的 uid/gid + rwx，应用只能访问自己沙箱和授权目录。
* SurfaceView、TextureView、SurfaceTexture、GLSurfaceView？
  答：SurfaceView 独立 Surface、子线程绘制、不能变换；TextureView 可做动画但耗内存；SurfaceTexture 输出 GL 纹理；GLSurfaceView 封装 EGL。
* Scroller 原理？
  答：配合 computeScroll 使用，按插值器和时长逐帧算出 scrollX/Y 再 invalidate；它只算值，不真正移动 View。
* RecyclerView 的性能优化
  答：setHasFixedSize、复用 ViewHolder、用 payload 做局部刷新、bind 里少做耗时/图片按需加载、DiffUtil 差量更新、避免嵌套滑动冲突。
* ListView 与 RecyclerView 简单对比?
  答：ListView 只支持纵向、ViewHolder 要手动优化、局部刷新弱；RecyclerView 强制 ViewHolder、LayoutManager 定布局、支持动画和分割线。
* Android类加载器
  答：PathClassLoader（加载已安装 apk 的 dex）、DexClassLoader（加载任意路径 dex/jar，需可写目录）、BootClassLoader，都继承 BaseDexClassLoader。
* onStart()与onResume()有什么区别？
  答：onStart 表示可见但不可交互（如被半透明页遮挡），onResume 表示回到前台、可交互并获得焦点。
* 说说 IdleHandler
  答：MessageQueue 空闲时（无消息或下条消息未到点）回调，适合延迟初始化；返回 false 表示只执行一次。
* 同步屏障机制(sync barrier)
  答：往队列插入 target 为 null 的屏障消息，拦住同步消息、只放行异步消息（如 VSYNC 的 doFrame），保证绘制优先。
* getWidth() 和 getMeasureWidth() 区别
  答：getMeasuredWidth 是 measure 后父容器给定的期望尺寸，getWidth 是 layout 后 right-left 的实际尺寸，一般两者相等。
* requestLayout，invalidate，postInvalidate 之间的区别？
  答：requestLayout 触发 measure+layout；invalidate 只重绘、必须在主线程；postInvalidate 可在子线程用，内部转 Handler。
* apk安装流程
  答：PackageInstaller 会话校验签名与权限→installd 解压、dexopt 到 /data/app→PMS 扫描登记→发 ACTION_PACKAGE_ADDED 广播。
* app 瘦身
  答：R8 + shrinkResources、移除无用资源与语言、图片转 WebP/AVIF、so 只留 armeabi-v7a/arm64、去重复依赖、资源混淆。
* 64k
  答：单个 dex 的方法引用数上限 65536（索引是 16 位），超了要开 multidex 或减少方法数；5.0 起原生支持 multidex。
* 遇到 Fragment 哪些问题？
  答：getActivity 为 null、状态丢失（commit 在 onSaveInstanceState 后）、Fragment 重叠、懒加载失效、持有 Activity 引用导致泄漏。
* View 绘制
  答：ViewRootImpl.performTraversals 驱动 measure→layout→draw（onMeasure/onLayout/onDraw），最后交 RenderThread 合成。
* 如何解决View的事件冲突？
  答：外部拦截法（父容器 onInterceptTouchEvent 判断）、内部拦截法（子 View requestDisallowInterceptTouchEvent），或改用 NestedScrolling。
* SharedPreferences 性能优化
  答：主线程用 apply、不要存大对象、批量操作合并一次提交、启动时避免同步读全量文件；高频读改写 MMKV 更合适。
* 内存缓存和磁盘缓存是怎么实现的？
  答：内存用 LruCache（LinkedHashMap 按访问顺序 + 容量淘汰），磁盘用 DiskLruCache（journal 日志 + 文件）；Glide 还加了活动资源和弱引用。
* PathClassLoader与DexClassLoader有什么区别？
  答：PathClassLoader 只能加载已安装 apk 的 dex；DexClassLoader 可加载任意目录的 dex/jar/apk（需可写优化目录），插件化、热修复常用。
* SQLite升级
  答：SQLiteOpenHelper 的 onUpgrade 按 version 逐级处理；加列用 ALTER TABLE ADD COLUMN，改列就建新表搬数据再改名，包在事务里。
* WebView优化
  答：预创建/复用 WebView、独立进程、拦截资源走本地缓存、减少 JS 注入、页面销毁时 destroy 并从父容器移除防泄漏。
* 什么是MeasureSpec？
  答：32 位 int：高 2 位 mode（EXACTLY/AT_MOST/UNSPECIFIED），低 30 位 size；由父 MeasureSpec 与子 LayoutParams 决定。
* Fragment的懒加载实现
  答：容器用 setMaxLifecycle(STARTED) 让不可见页停在 onStart，再在 onResume 里判断 isVisible + 首次标志位只加载一次。
* DataBinding了解吗，你能说说它具体实现原理吗，有那些缺点？
  答：编译期 apt 解析布局生成 ViewDataBinding，用 setTag 存 View 引用、用 Observable/BR 做观察者更新；缺点：编译慢、报错难定位、调试不直观。
* MVC、MVP、MVVM 之间有何区别？
  答：MVC 里 Controller（Activity）既管逻辑又管视图，易臃肿；MVP 用 Presenter + 接口解耦、需手动解绑；MVVM 用 ViewModel + 可观察数据驱动。
* 如何实现一个圆形头像？
  答：自定义 View 用 BitmapShader + drawCircle，或 Xfermode 裁剪；也可用第三方 circleCrop，注意抗锯齿和缩放后重绘。
* Apk 加密？
  答：整体加固（壳在运行时解密 dex）、R8 混淆、so 加壳、资源混淆（AndResGuard）、签名校验 + 反调试，四件套常一起用。
* Apk 打包流程？
  答：aapt2 编译资源并生成 R→kotlinc/javac 编译源码→D8 转 dex→打包进 apk→zipalign 对齐→apksigner 签名。
* Android 匿名共享内存
  答：Ashmem（6.0 起走 memfd），通过 fd 在进程间共享内存，Binder 可传 fd；Bitmap、Surface 的大块数据传输依赖它。
* MMKV 用过吗、原理？
  答：基于 mmap 的 key-value 存储，直接读写映射内存、省系统调用，用 protobuf 编码，支持多进程，比 SP 快且写入更安全。
* 界面刷新机制？
  答：invalidate 标脏→scheduleTraversals→插同步屏障→Choreographer 等 VSYNC→performTraversals→RenderThread 合成。
* 打包的时候 v1、v2、v3 签名有何区别？
  答：v1 是 JAR 签名、逐文件摘要、兼容性最好；v2 对整包签名、校验快（7.0 起）；v3 支持密钥轮换（9.0 起）；v4 配合增量安装。
* Activity启动过程
  答：startActivity→Instrumentation→ATMS 校验→进程不在则 Zygote fork→ActivityThread 收 LAUNCH_ACTIVITY→反射建 Activity→回调生命周期。
* ContentProvider启动过程
  答：handleBindApplication 里 installContentProviders，PMS 查 manifest→创建实例→onCreate→登记到 AMS。
* Service启动过程
  答：startService→AMS.startService→进程不在先拉起→scheduleCreateService→回调 onCreate/onStartCommand。
* 广播启动过程
  答：sendBroadcast→AMS.broadcastIntent→匹配静态（PMS 查表）和动态 Receiver→逐个 scheduleReceiver→主线程 onReceive。
* Binder机制
  答：一次拷贝的 IPC：客户端通过 BpBinder 把参数写进 Parcel，经 /dev/binder 由内核映射到服务端进程，服务端 BBinder.onTransact 执行并回写结果。
* 插件化
  答：DexClassLoader 加载插件 dex、AssetManager.addAssetPath 加载资源，再 Hook AMS/Instrumentation 或代理 Activity 绕过 manifest 校验。
* 组件化
  答：按业务拆 module，common 提供基础能力，用 ARouter 等路由解耦通信，Gradle 统一版本管理，模块可独立编译调试。
* 热修复
  答：类修复（Tinker 差分 dex、插桩改 Elements 或反射改 ClassLoader）+ 资源修复（AssetManager）+ so 修复；受加固和新版本限制。
* 换肤方案
  答：颜色和图片抽到皮肤包，用 LayoutInflater.Factory2 拦截创建 View 并替换背景/文字色，或换 AssetManager 重建 Resources。
* 事件分发
  答：自顶向下 dispatchTouchEvent→onInterceptTouchEvent，不拦截交给子 View，都不处理再冒泡到父 onTouchEvent。
* 绘制流程
  答：measure 量尺寸（onMeasure）、layout 定位置（onLayout）、draw 画内容（onDraw/onDispatchDraw 画子 View），由 ViewRootImpl 驱动。
* 源码分析
  * ARouter
    答：APT 生成路由表，编译期把 path→Activity 映射写进分组类，运行时按组加载并反射跳转，支持拦截器和参数注入。
  * ButterKnife
    答：早期用 APT + 反射绑定 View，现在推荐 ViewBinding（类型安全、零反射、编译期生成），ButterKnife 已停止维护。
  * Dagger2
    答：编译期注解处理器生成依赖注入代码，@Inject/@Component/@Module 组合，无反射；Hilt 就是它的 Android 封装。
  * EventBus
    答：订阅者用 @Subscribe 注册到单例，发布事件时按事件类型在 map 里找订阅者并反射调用，支持线程模式；现多用 Flow/SharedFlow。
  * Glide
    答：三级缓存（活动资源/内存 LruCache/磁盘）+ 生命周期绑定（RequestManager 跟随 Fragment）+ BitmapPool 复用；请求会暂停恢复。
  * GreenDao
    答：APT 生成 DAO 和实体，底层 SQLite，用 QueryBuilder 拼 SQL；现在更推荐 Room（编译期校验、协程/Flow 支持）。
  * Leakcanary
    答：用 ActivityLifecycleCallbacks 在 onDestroy 后弱引用观察对象，触发 GC 后 dump 堆，用 Shark 分析引用链找泄漏点并通知。
  * Okhttp
    答：分发器（同步/异步队列）+ 拦截器链（应用、重试、桥接、缓存、连接、网络）+ 连接池复用 + 缓存策略；支持 HTTP/2。
  * Retrofit
    答：把接口方法上的注解解析成 ServiceMethod，动态代理生成实现，交给 OkHttp 发请求，再用 Converter 反序列化、CallAdapter 适配返回类型。
  * RxJava
    答：观察者 + 操作符 + 线程调度的流式库，subscribeOn/observeOn 切换线程，背压靠 Flowable；现部分场景被协程 Flow 取代。
* 性能优化
  * 内存优化
    答：抓泄漏（LeakCanary/Profiler）、控制 Bitmap 尺寸、避免大对象和频繁 GC、用对象池，关注 PSS 和 GC 日志。
  * 绘制优化
    答：减少布局层级、去掉过度绘制（开发者选项看蓝/红区）、避免 onDraw 里 new 对象和耗时计算、用 clipRect 局部刷新。
  * 启动优化
    答：启动窗口 + 首帧、懒加载/异步初始化、按需加载 so 和 dex、ContentProvider 延迟、用 Trace 和 Baseline Profile 度量。
  * 数据存储优化
    答：批量写 + 事务、适当建索引、SP 换 MMKV/DataStore、大文件别放 SP、关注主线程磁盘 IO。
  * 网络优化
    答：连接复用、gzip/br 压缩、请求合并与缓存（HTTP 缓存/ETag）、弱网重试退避、DNS 优化，长连接走 HTTP/2。
  * 电量优化
    答：合并网络请求、少用高精度定位和唤醒锁、用 JobScheduler/WorkManager 做延迟任务、Doze 下适配、避免频繁轮询。
  * 包体积优化
    答：R8 + shrinkResources、WebP/AVIF、so 只保留需要的 ABI、资源混淆、动态下发，持续看 APK 体积趋势。
* Kotlin
  * 谈谈协程？
    答：用户态轻量线程，靠挂起函数把状态存到 Continuation 上，由调度器分配到线程池执行；可结构化并发、取消、异常传播，比线程省资源。
  * List 与 MutableList 的区别？
    答：List 是只读接口（无 add/remove），MutableList 是读写接口；本质都是同一个 ArrayList，只是类型层面限制写操作。
  * let、with、run、apply、also 之间的区别应用场景？
    答：let 用 it 返回最后一行（空判断）；run 用 this 返回最后一行；with 用 this 返回最后一行；apply 用 this 返回自身（配置对象）；also 用 it 返回自身（附加操作）。
  * 注解 @JvmOverloads 的作用？
    答：给带默认参数的函数生成多个 Java 重载，方便 Java 调用；用在构造器上时需注意与 @JvmField 等配合。
  * 实现单例的几种常见方式？
    答：object 声明；companion object + lazy；双重检查（@Volatile + synchronized）；静态内部类；枚举。Android 里最常用 object 或 Hilt @Singleton。
  * data class 理解？
    答：自动生成 equals/hashCode/toString/copy/componentN；主构造至少要有一个参数，不能是 abstract/open/sealed，也不能继承其他 data class。
  * 集合遍历有哪几种方式？
    答：for-in（迭代器）、forEach、forEachIndexed、map/filter 等操作符、indices 下标遍历、iterator 手动遍历；Sequence 可惰性遍历。
  * 什么是委托属性？请简要说说其使用场景和原理？
    答：把属性的 get/set 委托给另一个对象（by 关键字），编译器生成 getValue/setValue 调用；典型：lazy、observable、非空断言、SharedPreferences 封装。
  * Kotlin中 Unit 类型的作用以及与Java中 Void 的区别？
    答：Unit 是真实的单例对象类型，可以作为泛型参数、有实例（Unit 本身）；Java 的 void 是关键字、没有值、不能作泛型参数。
  * Kotlin 中 infix 关键字的原理和使用场景？
    答：中缀调用就是把成员/扩展函数写成 a to b 的形式，要求单参数、非可变参数、非默认参数；如 to、shl、until、and。
  * "==" 和 "===" 区别？
    答：== 等价于 equals，比较内容（编译后调 equals）；=== 是引用比较，比较是否同一个对象地址。
  * 介绍一下伴生对象和静态成员？
    答：companion object 是类内部的单例对象，可通过 @JvmStatic 生成真正的静态方法给 Java 用；常量用 const val 才有编译期内联。
  * kotlin 中 var、val、const val 区别？
    答：var 可变；val 只读引用（对象内容可变）；const val 是编译期常量，只能修饰顶层或 object 中的基本类型/String。
  * @JvmField 和 @JvmStatic 的使用
    答：@JvmField 把属性暴露成 Java 的 public 字段（省 getter）；@JvmStatic 让 companion object/object 的成员生成静态方法，供 Java 直接调用。
  * @JvmOverloads 的作用？
    答：为带默认值的参数生成一系列重载，Java 侧就不用写全部参数；Kotlin 调 Kotlin 时其实用不到。
  * List 与 MutableList 区别？
    答：List 只读、MutableList 可写；两者底层都是 ArrayList，区别只在编译期接口约束，可用 as MutableList 强转但运行时才报错。
  * Kotlin 中的数据类型有隐式转换吗？
    答：没有。Int 不会自动转 Long/Double，必须显式调用 toLong()/toDouble() 等方法，避免精度和类型歧义。
  * Kotlin中的可见性修饰符有哪些？相比于 Java 有什么区别？
    答：private、protected、internal、public；默认是 public，多了模块级 internal；protected 不包访问、子类可见。
  * 在 Kotlin 中，什么是内联函数？有什么作用？
    答：inline 让编译器把函数体直接展开到调用处，省去 lambda 对象和函数调用开销；配合 reified 可保留泛型类型，注意别内联大函数。
  * 谈谈 Kotlin 中的 Sequence，为什么它处理集合操作更加高效？
    答：Sequence 是惰性求值，链式操作不生成中间集合、可短路（如 first），适合大数据量多步操作；集合操作则每步都建新集合。
  * 请谈谈 Kotlin 中的 Coroutines，它与线程有什么区别？有哪些优点？
    答：协程跑在线程上，可挂起而不阻塞线程，切换成本低、可成千上万；支持结构化并发、取消、异常传播，代码还是同步写法。
  * Kotlin 中可见性修饰符有哪些？相比于Java有什么区别？
    答：private、protected、internal、public；默认 public，多了 internal（模块内可见），protected 只对子类可见、不含包级。
  * 谈谈 Kotlin 中的Unit？它和 Java 中的 void 有什么区别？
    答：Unit 是单例对象类型、有唯一实例、可作泛型参数；void 只是"无返回值"的标记，不是类型也没有值。
  * 如何安全地处理可空类型？
    答：用 ?. 安全调用、?: 给默认值、!! 强解包（会 NPE，慎用）、let 配合 ?.、requireNotNull/checkNotNull 提前校验。
  * 说说 Kotlin中 的 Any 与 Java 中的 Object 有何异同？
    答：Any 是所有非空类型的根，等价于 Object 但不含 null；Any? 才对应 Object；Any 只声明 equals/hashCode/toString。
  *  Kotlin中 Unit 类型的作用以及与Java中 Void 的区别？
    答：Unit 表示"无有意义返回值但有值"，是类型、可作泛型参数；Void 只是 void 的包装类，通常为 null 且很少直接用。
  * 分别通过对象表达式 object 和 lambda 表达式实现的函数式接口内部有何不同？
    答：object 表达式生成匿名内部类、每次新建实例、可实现多方法；lambda 由 LambdaMetafactory 生成，只在单抽象方法（SAM）时能用。
* Compose 和传统 View 的区别？
  答：Compose 声明式、状态驱动重组、无 XML 和 View 树；View 命令式、手动改属性。Compose 只重组读到变化 State 的部分。
* Compose 的重组（recomposition）是怎么触发的？怎么优化？
  答：读到的 State 变了就重组。优化：remember/derivedStateOf 缓存计算、数据类用 immutable、list 的 key 稳定、把状态读取下沉到叶子节点。
* Compose 的 remember 和 rememberSaveable 区别？
  答：remember 只在组合内缓存，重建就丢；rememberSaveable 通过 Saver 存进 Bundle，旋转或进程重建后能恢复（LazyListState 已内置）。
* 协程的作用域有哪些？launch 和 async 区别？
  答：GlobalScope（别用）、viewModelScope、lifecycleScope、rememberCoroutineScope；launch 返回 Job 无结果，async 返回 Deferred 可 await。
* 协程的取消是协作式的，怎么保证正确取消？
  答：挂起点（delay/await/withContext）会自动检查；CPU 密集循环里手动 ensureActive()，取消后 finally 做清理，别吞 CancellationException。
* 结构化并发是什么？有什么好处？
  答：父作用域管理子协程，子没完成父不结束，一个子失败会取消兄弟、父取消会取消全部；避免泄漏，异常自动向上传播。
* Flow、StateFlow、SharedFlow 区别？
  答：Flow 是冷流、每个收集者独立执行；StateFlow 是热流、有初始值、去重后只留最新值（存 UI 状态）；SharedFlow 无初始值、可配重放（发事件）。
* Hilt 和 Dagger 是什么关系？作用域有哪些？
  答：Dagger 的 Android 封装，@HiltAndroidApp + @AndroidEntryPoint 省去手写组件；作用域有 Singleton、ActivityScoped、ViewModelScoped。
* targetSdk 35 强制边到边（edge-to-edge），怎么适配？
  答：用 enableEdgeToEdge() 或 setDecorFitsSystemWindows(false)，再按 WindowInsets 给根布局加 padding；别写死状态栏高度，注意输入法遮挡。
* targetSdk 36（Android 16）有哪些行为变更？
  答：强制边到边、大屏（≥600dp）忽略方向与 resizable 限制、预测性返回默认开启、16KB 页对齐、JobScheduler 配额更严。
* Android 15 起的 16 KB 内存页适配要做什么？
  答：原生 so 必须按 16KB 对齐（NDK r28+ / zipalign -P 16），否则在 16KB 页设备上加载失败；升级 AGP 与 NDK 并检查所有三方 so。
* Android 14/15 对前台服务有哪些限制？
  答：必须声明 foregroundServiceType 并申请对应权限；15 起 dataSync、mediaProcessing 等类型有每日时长上限，超时系统会停掉服务。
* POST_NOTIFICATIONS 权限怎么处理？
  答：13 起发通知要动态申请 POST_NOTIFICATIONS，拒绝后只能引导去设置；先查 areNotificationsEnabled 再请求，别一启动就弹。
* Baseline Profile 是什么？有什么用？
  答：记录启动与关键路径的方法执行，打进 apk 让 ART 安装时 AOT 编译热路径，明显改善冷启动和首屏卡顿。

## 4 计算机基础知识点

* tcp/ip 流量控制和滑动窗口如何实现的，能具体说说嘛？
  答：接收方通过窗口字段通告可接收字节数，发送方据此控制未确认数据量；窗口随处理能力动态调整，配合累计确认实现流量控制。
* DNS 解析过程？
  答：查浏览器/系统缓存→hosts→本地 DNS 递归→根→顶级域→权威服务器，返回 IP 并逐级缓存；默认 UDP 53，大包或 DNSSEC 用 TCP。
* 三次握手和四次挥手？
  答：握手：SYN→SYN+ACK→ACK，确认双方收发能力；挥手：FIN→ACK→FIN→ACK，因为 TCP 全双工，两个方向要各自关闭。
* 谈谈 TCP/IP 协议？
  答：四层模型：应用层（HTTP/DNS）、传输层（TCP/UDP）、网络层（IP/ICMP）、链路层（以太网）；每层封装自己的头部再交给下一层。
* TCP 协议如何保证可靠传输？
  答：序号 + 确认应答 + 超时重传 + 校验和 + 滑动窗口流量控制 + 拥塞控制 + 乱序重排与去重。
* 拥塞控制的算法？
  答：慢开始（指数增长）、拥塞避免（线性增长，超过 ssthresh）、快重传（三个重复 ACK）、快恢复（减半后继续拥塞避免）。
* 在浏览器中输入 url 地址发生了什么？
  答：DNS 解析→TCP 连接（HTTPS 还要 TLS 握手）→发 HTTP 请求→服务端响应→浏览器解析渲染→断开或复用连接。
* URI 和 URL 的区别是什么？
  答：URI 是统一资源标识符，只要能唯一标识资源即可；URL 是 URI 的子集，还包含定位方式（协议 + 主机 + 路径）。
* HTTP1.0、HTTP2.0、HTTP3.0 区别？
  答：1.0 短连接、队头阻塞；2.0 二进制分帧 + 多路复用 + 头部压缩，但 TCP 层仍阻塞；3.0 基于 QUIC/UDP，解决 TCP 队头阻塞、0-RTT。
* HTTP 和 HTTPS 区别？
  答：HTTPS 是 HTTP + TLS，加密传输、防篡改、用证书验证身份，默认 443（HTTP 80）；代价是多一次握手和证书成本。
* 进程和线程区别？
  答：进程是资源分配单位、地址空间独立；线程是调度单位、共享进程内存，创建切换开销更小，一个进程可含多个线程。
* 进程有那几种的状态？
  答：新建、就绪、运行、阻塞（等待 I/O 或事件）、终止；运行态时间片用完回就绪，等待事件完成再回就绪。
* 进程间有哪几种通信方式？
  答：管道、命名管道、消息队列、共享内存（最快）、信号量、信号、Socket；Android 上主要是 Binder，还有 Provider、共享文件。
* 线程间的同步方式？（互斥量、信号量、事件）
  答：互斥量保证临界区互斥，信号量控制并发数量，事件/条件变量用于等待通知；Java 里对应 synchronized、Semaphore、wait/notify。
* 进程间的调度算法？
  答：先来先服务、短作业优先、时间片轮转、优先级调度、多级反馈队列、高响应比优先；目标兼顾吞吐、响应和公平。
* 页面置换算法？
  答：OPT（理论最优，用作基准）、FIFO（有 Belady 异常）、LRU（最近最少使用，常用）、Clock（LRU 的近似实现）、LFU。

* 剑指Offer
  * 数组中重复的数字
    答：原地交换把 nums[i] 归位到下标 i，发现 nums[i] == nums[nums[i]] 即重复；O(n) 时间 O(1) 空间。
  * 二维数组中的查找
    答：从右上角出发，比目标大就往左、小就往下，最多走 m+n 步，O(m+n)。
  * 替换空格
    答：先统计空格数算出新长度，再从后往前双指针填充 %20，避免反复搬移，O(n)。
  * 从尾到头打印链表  重建二叉树
    答：打印用递归或辅助栈逆序；重建二叉树用前序首元素切分中序，左右递归建树。
  * 用两个栈实现队列
    答：入队压 in 栈，出队时若 out 为空就把 in 全部倒入 out，再弹出栈顶。
  * 斐波那契数列
    答：迭代 a, b = b, a + b，O(n) 时间 O(1) 空间；别写重复计算的递归。
  * 青蛙跳台阶问题
    答：本质是斐波那契，f(n) = f(n-1) + f(n-2)；大数时取模或转字符串。
  * 旋转数组的最小数字
    答：二分：nums[mid] 与右端比较缩小区间；有重复元素时 right-- 退化为线性。
  * 矩阵中的路径
    答：DFS + 回溯，访问过的格子临时置空或标记，越界或字符不等就剪枝。
  * 机器人的运动范围
    答：DFS/BFS 遍历，判断坐标数位和 ≤ k，记录 visited 防重复计数。
  * 剪绳子
    答：数学贪心：尽量拆成 3，余 1 时改成 2+2；也可用 DP 求最大乘积。
  * 剪绳子 II
    答：同剪绳子，但结果对 1e9+7 取模，用循环快速幂避免溢出。
  * 二进制中1的个数
    答：n & (n-1) 每次消掉最低位的 1，循环次数即 1 的个数。
  * 数值的整数次方
    答：快速幂：底数平方、指数折半；负指数先取倒数，注意 0 的负数次方和溢出。
  * 打印从1到最大的n位数
    答：n 大时用字符串/DFS 全排列，处理前导零，避免 int 溢出。
  * 删除链表的节点
    答：用哨兵或 pre 指针改 next 跳过目标节点；值可能有多个时用双指针边遍历边删。
  * 正则表达式匹配
    答：记忆化递归或 DP：处理 '.' 匹配任意字符、'*' 匹配 0 次或多次。
  * 表示数值的字符串
    答：逐字符状态机：处理正负号、小数点、e/E 指数，各状态非法输入直接返回 false。
  * 调整数组顺序使奇数位于偶数前面
    答：左右双指针相向走，遇到左边偶、右边奇就交换，O(n) 原地。
  * 链表中倒数第k个节点
    答：快指针先走 k 步，然后快慢一起走，快到头时慢指针就是答案。
  * 反转链表
    答：迭代三指针 prev/cur/next 逐个改指向；或递归让 head.next.next = head。
  * 合并两个排序的链表
    答：哨兵 dummy + 尾指针，比较后接入较小者，最后拼上剩余部分。
  * 树的子结构
    答：先序遍历 A 的每个节点，用 isSame 递归比较以该节点为根的子树与 B。
  * 二叉树的镜像
    答：递归交换左右子树再分别镜像；也可用栈做迭代。
  * 对称的二叉树
    答：递归比较 left.right 与 right.left、left.left 与 right.right。
  * 顺时针打印矩阵
    答：维护上下左右四个边界，逐边打印后收缩；注意最后单行/单列别重复打印。
  * 栈的压入、弹出序列
    答：按下序依次入栈，栈顶等于出栈序列当前值就弹出，最后栈空即合法。
  * 从上到下打印二叉树
    答：BFS，用队列逐层出队并把子节点入队。
  * 从上到下打印二叉树 II
    答：BFS 前先记下当前层 size，循环 size 次收集一层；整体是一个二维数组。
  * 从上到下打印二叉树 III
    答：之字形：偶数层直接追加、奇数层头插；或用双端队列按层交替方向。
  * 二叉搜索树的后序遍历序列
    答：末尾是根，前面按比根大/小切成左右子树，递归校验每段都满足 BST。
  * 复杂链表的复制
    答：哈希表映射旧节点→新节点；或原地复制节点后用指针关系拆成两条链（O(1) 空间）。
  * 二叉搜索树与双向链表
    答：中序遍历有序，用 pre 指针把节点串成双向链表，最后首尾相连成环。
  * 序列化二叉树
    答：前序遍历 + 空节点占位符；反序列化按下标递归还原左右子树。
  * 字符串的排列
    答：回溯：固定一位、交换后续；同层用 set 去重，避免重复排列。
  * 数组中出现次数超过一半的数字
    答：摩尔投票：计数为 0 换候选，否则相同 +1、不同 -1；最后再验证一遍。
  * 最小的k个数
    答：大顶堆维持 k 个（O(n log k)）；或快选 partition 找第 k 小后取前 k。
  * 数据流中的中位数
    答：大顶堆存较小一半、小顶堆存较大一半，保持 size 差 ≤ 1，中位数取自堆顶。
  * 连续子数组的最大和
    答：Kadane：cur = max(x, cur + x)，同时更新全局最大；全负时取最大单值。
  * 1～n 整数中 1 出现的次数
    答：按位统计：对每一位取 high、cur、low，按 cur 为 0/1/大于 1 分别累加。
  * 数字序列中某一位的数字
    答：先定位属于几位数（1~9、10~99…），再算出该数与该位下标。
  * 把数组排成最小的数
    答：自定义比较器比 a+b 与 b+a 的字典序，排序后拼接；需处理大数字符串。
  * 把数字翻译成字符串
    答：DP：dp[i] = dp[i-1] +（两位在 10~25 时加 dp[i-2]）。
  * 礼物的最大价值
    答：二维 DP：dp[i][j] = max(上, 左) + grid[i][j]，可滚动成一维。
  * 最长不含重复字符的子字符串
    答：滑动窗口 + 哈希记录字符上次位置，左边界取 max(左, 上次+1)，更新最大长度。
  * 丑数
    答：三指针分别乘 2/3/5 取最小放进数组，相同值只推进一次。
  * 第一个只出现一次的字符

  * 两个链表的第一个公共节点

  * 平衡二叉树
    答：后序求高度，同时判断 |左 - 右| ≤ 1，不平衡返回 -1 提前剪枝。
  * 数组中数字出现的次数
    答：全部异或得到 a^b，取最低位的 1 分组，两组分别异或得到 a 和 b。

  * 把字符串转换成整数

  * 二叉搜索树的最近公共祖先

* 排序算法
  * 冒泡排序
    答：相邻两两比较交换，每轮冒出一个最大值；加标志可提前退出，稳定，O(n²)。
  * 选择排序
    答：每轮选出最小值放到已排序段末尾；交换次数少但比较固定 O(n²)，不稳定。
  * 插入排序
    答：把当前元素插入前面已排好序的段；近乎有序时接近 O(n)，稳定。
  * 希尔排序
    答：按增量分组做插入排序，增量递减到 1；不稳定，平均约 O(n^1.3)。
  * 归并排序
    答：分治到单个元素再两两合并有序段；稳定，O(n log n)，需 O(n) 额外空间。
  * 快速排序
    答：选基准 partition 后递归两侧；平均 O(n log n)、最坏 O(n²)，不稳定，工程上用三数取中 + 小区间插入。
  * 堆排序
    答：建大顶堆后反复交换堆顶与末尾并下沉；O(n log n)、原地，不稳定。
  * 计数排序
    答：统计每个值的出现次数再前缀和回填位置；O(n + k)，只适合范围小的整数。
  * 桶排序
    答：按值域分桶、桶内排序再拼接；平均 O(n)，适合分布均匀的数据。
  * 基数排序
    答：从低位到高位按位做稳定排序（计数排序实现）；O(d(n + k))，适合定长整数/字符串。
