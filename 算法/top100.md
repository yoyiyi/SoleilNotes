# LeetCode 热题 HOT 100

HOT 100 是 LeetCode 官方从题库里筛出的 100 道高频面试题，覆盖哈希、双指针、滑动窗口、子串、数组、矩阵、链表、二叉树、图论、回溯、二分、栈、堆、贪心、动态规划、技巧等主干知识点。它的价值不在于「刷完 100 道」这个数字，而在于用最少的题量把面试常考的模型过一遍：其中大多数是模板题，少数（如 42.接雨水、76.最小覆盖子串、4.寻找两个正序数组的中位数）是用来拉开差距的难题。

这份笔记怎么用：

* 一刷按下面的分类顺序推进，一类一类过，重点记每类题的「识别信号」和「代码模板」，难题不必死磕。
* 每道题只看「思路 + 复杂度」自测：能不能在 30 秒内说出做法，能不能在白板上写出来。
* 二刷按题号乱序，专门练「看到题目就知道该用哪个模型」。
* 标记过的题（没思路、写错、调了很久）进错题清单，考前只刷错题。

每题给出难度、一句话思路与时间/空间复杂度；其中 5 道最经典的题（1、206、102、46、300）附可直接运行的 Java 完整题解，用 `#### 完整题解` 标出。

## 一、哈希

### 1. 两数之和

难度 简单

思路：一次遍历，哈希表存「值 → 下标」，对 nums[i] 先查 target - nums[i] 是否出现过，命中即返回两个下标，否则把当前值入表。

复杂度：时间 O(n)，空间 O(n)。

#### 完整题解

暴力双重循环是 O(n²)，面试里写出来基本等于没做。关键在于把「找补数」这一步降到 O(1)：遍历到 nums[i] 时，如果 target - nums[i] 已经在表里，说明前面出现过它的搭档，直接返回两个下标即可。

先查后存这个顺序很重要：它保证了不会把同一个元素用两次（数组里有重复值、且 target 恰好是某个值的两倍时最容易踩坑）。

```java
class Solution {
    public int[] twoSum(int[] nums, int target) {
        // 值 -> 下标；边遍历边建表，保证查到的都是「之前出现过」的元素
        Map<Integer, Integer> map = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            int need = target - nums[i];
            // 先查后存：既能避免同一个元素被用两次，也省掉了判重逻辑
            if (map.containsKey(need)) {
                return new int[]{map.get(need), i};
            }
            map.put(nums[i], i);
        }
        // 题目保证有且只有一个答案，正常不会走到这里
        return new int[]{-1, -1};
    }
}
```

注意：题目保证唯一解，所以循环外返回什么并不影响通过；但如果面试官要求「不存在时返回空数组」，这里就应该改成 `new int[0]`。

## 二、双指针

### 283. 移动零

难度 简单

思路：快慢指针，慢指针指向下一个非零元素该落的位置，快指针扫到非零值就前移，最后把慢指针之后的元素全部补零。

复杂度：时间 O(n)，空间 O(1)。

### 11. 盛最多水的容器

难度 中等

思路：左右指针从两端向中间收，每次移动较短的那一侧（移动长边不可能让面积变大），途中用 min(h[l], h[r]) × (r - l) 更新答案。

复杂度：时间 O(n)，空间 O(1)。

### 15. 三数之和

难度 中等

思路：先排序，枚举第一个数并跳过重复值，剩余部分用左右指针凑 -nums[i]，命中后两侧同时跳过重复元素。

复杂度：时间 O(n²)，空间 O(1)（不计排序与结果）。

### 42. 接雨水

难度 困难

思路：每个位置能接的水是 min(左侧最大高度, 右侧最大高度) - height[i]，用左右双指针边走边维护两侧最大值即可一次遍历求和。

复杂度：时间 O(n)，空间 O(1)。

## 三、滑动窗口

### 3. 无重复字符的最长子串

难度 中等

思路：右指针扩张、左指针收缩，用哈希表记录字符最近出现的下标，遇到重复就把左指针跳到「上次出现位置 + 1」，全程维护窗口最大值。

复杂度：时间 O(n)，空间 O(字符集大小)。

### 438. 找到字符串中所有字母异位词

难度 中等

思路：固定长度等于 p 的窗口在 s 上滑动，用长度 26 的计数数组比较窗口与 p 的字符频次，相等就记录左端点。

复杂度：时间 O(n + m)，空间 O(1)（26 个计数位）。

## 七、链表

### 160. 相交链表

难度 简单

思路：两个指针分别从 headA、headB 出发，走到末尾就换到另一条链表头继续走，路程差被抵消，相遇点即交点。

复杂度：时间 O(m + n)，空间 O(1)。

### 206. 反转链表

难度 简单

思路：三指针迭代，prev 初始为 null，每步先暂存 cur.next，再让 cur.next 指向 prev，最后 prev 与 cur 同步后移。

复杂度：时间 O(n)，空间 O(1)。

#### 完整题解

迭代写法的核心是「先存后继再改指针」，顺序反了就会断链。循环结束时 cur 为 null，prev 正好停在新链表的头结点上。

```java
class Solution {
    public ListNode reverseList(ListNode head) {
        ListNode prev = null;  // 已反转部分的头结点
        ListNode cur = head;   // 当前待处理的结点
        while (cur != null) {
            ListNode next = cur.next; // 必须先存后继，否则改完指针就找不到后面的结点了
            cur.next = prev;          // 反向指回前驱
            prev = cur;               // prev 前移一位
            cur = next;               // cur 前移一位
        }
        // 循环结束时 cur 为 null，prev 就是新链表的头
        return prev;
    }
}
```

递归写法只需三行（`head.next.next = head; head.next = null;`），但递归深度是 n，链表很长时会爆栈，面试里优先写迭代。

### 102. 二叉树的层序遍历

难度 中等

思路：队列逐层遍历，每轮先固定当前队列长度，一次性弹出这一层的全部结点并把它们的非空孩子入队。

复杂度：时间 O(n)，空间 O(n)。

#### 完整题解

层序遍历的模板价值极高，二叉树的右视图、每层最大值、锯齿遍历、最小深度都是在这段代码上改一两行。唯一的关键点是：进入内层循环前必须先把 `size` 固定下来，否则新入队的下一层结点会被混进当前层。

```java
class Solution {
    public List<List<Integer>> levelOrder(TreeNode root) {
        List<List<Integer>> res = new ArrayList<>();
        if (root == null) {
            return res; // 空树返回空列表，不是返回 null
        }
        Deque<TreeNode> queue = new ArrayDeque<>();
        queue.offer(root);
        while (!queue.isEmpty()) {
            int size = queue.size(); // 当前层的结点数，必须在循环前固定
            List<Integer> level = new ArrayList<>(size);
            for (int i = 0; i < size; i++) {
                TreeNode node = queue.poll();
                level.add(node.val);
                // 空孩子不入队，省去后续判空
                if (node.left != null) {
                    queue.offer(node.left);
                }
                if (node.right != null) {
                    queue.offer(node.right);
                }
            }
            res.add(level);
        }
        return res;
    }
}
```

改成「右视图」只需在 `level` 之后记录最后一个元素，或者把入队顺序改成先右后左、每层只取第一个。

### 994. 腐烂的橘子

难度 中等

思路：多源 BFS，把所有腐烂橘子同时入队，按层扩散并统计层数，结束后若还有新鲜橘子则返回 -1。

### 207. 课程表

难度 中等

### 208. 实现 Trie (前缀树)

## 十、回溯

### 46. 全排列

难度 中等

思路：用 used 数组标记已选元素，递归在每一层枚举所有未使用的数，路径长度等于 n 时收集结果。

复杂度：时间 O(n·n!)，空间 O(n)。

#### 完整题解

回溯的通用骨架是「选择 → 递归 → 撤销选择」，全排列是最干净的模板：每层从所有元素里挑一个没用过的，挑满 n 个就得到一个排列。

两个必须写对的细节：结果收集时要 `new ArrayList<>(path)` 拷贝一份，因为 path 全程复用；递归返回后要同时撤销 `path` 末尾元素和 `used` 标记。

```java
class Solution {
    public List<List<Integer>> permute(int[] nums) {
        List<List<Integer>> res = new ArrayList<>();
        boolean[] used = new boolean[nums.length];
        backtrack(nums, used, new ArrayList<>(), res);
        return res;
    }

    private void backtrack(int[] nums, boolean[] used, List<Integer> path, List<List<Integer>> res) {
        // 终止条件：路径长度等于数组长度，说明凑满了一个排列
        if (path.size() == nums.length) {
            res.add(new ArrayList<>(path)); // 必须拷贝，path 之后还会被修改
            return;
        }
        for (int i = 0; i < nums.length; i++) {
            if (used[i]) {
                continue; // 已经在路径里的元素不能再选
            }
            used[i] = true;      // 做选择
            path.add(nums[i]);
            backtrack(nums, used, path, res);
            path.remove(path.size() - 1); // 撤销选择
            used[i] = false;
        }
    }
}
```

如果数组里有重复元素，需要先排序，再加上 `if (i > 0 && nums[i] == nums[i-1] && !used[i-1]) continue;` 跳过同层重复，这就是「全排列 II」的解法。

## 十一、二分查找

### 35. 搜索插入位置

难度 简单

### 74. 搜索二维矩阵

难度 中等

复杂度：时间 O(log(m·n))，空间 O(1)。

### 34. 在排序数组中查找元素的第一个和最后一个位置

难度 中等

思路：写两次二分，一次找第一个大于等于 target 的下标，一次找第一个大于 target 的下标再减一，最后校验越界与值是否匹配。

### 33. 搜索旋转排序数组

难度 中等

思路：二分时判断哪一半有序（nums[mid] 与 nums[left] 比较），若 target 落在有序那一半的范围内就收缩到该半，否则去另一半。

### 153. 寻找旋转排序数组中的最小值

难度 中等

思路：二分比较 nums[mid] 与 nums[right]，mid 大于右端说明最小值在右半，否则在左半（含 mid）。

复杂度：时间 O(log n)，空间 O(1)。

### 4. 寻找两个正序数组的中位数

难度 困难

思路：在较短数组上二分分割点，使左半部分元素个数为 (m+n+1)/2 且 max(左) ≤ min(右)，中位数由分割线两侧的四个值算出。

复杂度：时间 O(log(min(m, n)))，空间 O(1)。

### 279. 完全平方数

### 139. 单词拆分

### 300. 最长递增子序列

难度 中等

思路：f[i] 表示以 nums[i] 结尾的最长递增子序列长度，f[i] = max(f[j]) + 1（j < i 且 nums[j] < nums[i]）；进阶用贪心 + 二分做到 O(n log n)。

复杂度：时间 O(n²)（二分法 O(n log n)），空间 O(n)。

#### 完整题解

O(n²) 的 DP 定义很直观：以每个位置结尾往前找能接上的最长序列。但更值得背下来的是「贪心 + 二分」版本：维护一个数组 tails，`tails[k]` 表示长度为 k+1 的递增子序列的最小结尾值，结尾越小后面越容易接上，所以它天然单调递增，可以用二分定位。

注意 tails 本身并不是某个真实的子序列，它只是「各长度的最小结尾」这个信息。

```java
class Solution {
    public int lengthOfLIS(int[] nums) {
        // tails[k] = 所有长度为 k+1 的递增子序列中，最小的结尾值
        int[] tails = new int[nums.length];
        int len = 0; // 当前能凑出的最长长度
        for (int x : nums) {
            // 在 tails[0, len) 中二分找第一个 >= x 的位置
            int left = 0;
            int right = len;
            while (left < right) {
                int mid = left + (right - left) / 2;
                if (tails[mid] < x) {
                    left = mid + 1;
                } else {
                    right = mid;
                }
            }
            // 用 x 替换掉那个位置，让该长度的结尾尽量小
            tails[left] = x;
            // 如果接在了末尾，说明找到了更长的子序列
            if (left == len) {
                len++;
            }
        }
        return len;
    }
}
```

二分边界是这题最容易写错的地方：找的是「第一个大于等于 x」的位置，用 `left < right` 的写法比 `left <= right` 更不容易死循环。

### 常见失分点

* 哈希：两数之和把「先查后存」写反，同一个元素被用了两次；字母异位词分组用计数数组当键时，没有转成 List 或字符串，导致哈希比较永远不相等。
* 双指针：三数之和只对第一个数去重、忘了左右指针命中后也要跳过重复，结果出现重复三元组；接雨水误以为该移动较长的那一侧。
* 滑动窗口：窗口收缩写成 if，实际应该用 while 收缩到合法；最小覆盖子串每次都遍历整个计数表比较，复杂度退化。
* 链表：反转链表没先保存 next 导致断链；删除倒数第 N 个结点不用哑结点，删头结点时直接空指针。
* 二叉树：验证 BST 只比较父子结点而不传上下界，「右子树的左孩子比根小」这类情况会漏判；最近公共祖先没考虑 p 是 q 祖先的情形。
* 回溯：收集结果时忘了 `new ArrayList<>(path)`，最后得到一个空列表；剪枝条件写在收集结果之后，等于没剪。
* 二分：mid 写成 (left + right) / 2 在极端数据下溢出；区间定义（左闭右闭还是左闭右开）与边界更新方式不匹配，导致死循环或漏解。
